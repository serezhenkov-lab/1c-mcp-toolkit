# Проверка режимов подтверждения

`form_tests.bsl` выполняется на платформе 1С в копии настоящей формы Toolkit.
`prepare_runtime.py` копирует исходники только в **новый** каталог внутри `.local`,
добавляет тестовый обработчик после штатного открытия формы и пишет отчёт рядом с копией.
В исходники и поставляемую EPF тестовый обработчик не попадает.

Пример подготовки из корня репозитория:

```text
python tests/approval_modes/prepare_runtime.py .local/approval-modes/run-001
```

Собрать `.local/approval-modes/run-001/MCPToolkit.xml` обычным сборщиком EPF.
Запускать полученную **тестовую** EPF только в новой пустой файловой базе:
тесты изменяют её настройки Toolkit и создают два новых текстовых файла возле отчёта.
Для повторного запуска выбрать новый каталог подготовки, чтобы результаты и файлы
предыдущего запуска не подменяли новые доказательства. После открытия обработки
тесты выполняются автоматически и завершают сеанс 1С. При штатном предупреждении
1С об открытии внешней обработки требуется разрешить именно эту тестовую EPF.

Проверяются: миграция старого флага, безопасный код, запрет при старых автофлагах,
разовое подтверждение и его погашение, изменение кода/контекста до и после решения,
серия удалений элементов массива без диалогов, сохранение только deny/ask, отзыв выбором ask в поле,
устаревшее окно с повторным request ID, настройки очереди и выполняющейся команды,
реальные записи из client/server контекста и отсутствие записи при запрете.

Дополнительно проверяется результат третьей кнопки `session_allow`: текущая и
следующая команды, значение поля режима, сохранение только ask, отказ и закрытие
окна, изменение кода/контекста, отзыв и старый сеанс. Для маршрутов mcp/rest/proxy
проверяются отсутствующая, отменённая и просроченная ожидающая операция, изменение
настроек и сохранение актуальности текущей команды при переходе в очередь.
Это проверки обработчиков на платформе, а не сквозные сетевые вызовы или клики UI.

Эти автотесты проверяют исполнение BSL и обработчики решений. Они не заменяют
ручную проверку вида формы, реальных кликов подтверждения, перезапуска 1С через
MCP и испытания параллельных фоновых заданий в клиент-серверной базе.

Python-регрессия из корня репозитория: `python -m unittest discover -s tests -v`.
Нужны зависимости proxy; работающий сервер для тестов не требуется.
