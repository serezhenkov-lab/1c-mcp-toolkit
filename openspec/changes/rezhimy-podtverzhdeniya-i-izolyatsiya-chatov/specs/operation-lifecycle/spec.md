## Purpose

Получение статуса и позднего результата без повторного исполнения после таймаута.

## ADDED Requirements

### Requirement: Статус и поздний результат

<a id="ol-01"></a>

Toolkit SHALL выдавать operation_id и предоставлять через native MCP состояние и результат операции. Состояние SHALL различать ожидание подтверждения/очереди, выполнение, подтверждённый итог и unknown. Таймаут ожидания ответа SHALL не удалять запись операции или её поздний результат. Статус SHALL быть доступен без повторного запуска кода.

#### Scenario: Поздний успех
- **WHEN** клиент перестал ждать, но команда затем завершилась успешно
- **THEN** результат можно получить по прежнему ID в пределах объявленного срока хранения; таймаут не выдаётся за отмену.

#### Scenario: Ожидание решения
- **WHEN** операция ожидает разрешения пользователя
- **THEN** доступны её ID и статус ожидания без удержания транзакции базы; чтение статуса не запускает команду повторно.

### Requirement: Повтор и восстановление состояния

<a id="ol-02"></a>

Повтор обращения к принятой операции SHALL возвращать её состояние/результат без нового исполнения. Иной код под тем же ключом SHALL отклоняться. После сбоя с неизвестным исходом SHALL сохраняться unknown, без автоматического повтора. Хранение SHALL быть ограниченным с явным result_expired; очистка истории SHALL не разрешать повтор старой команды.

#### Scenario: Повтор после таймаута
- **WHEN** клиент повторяет обращение с тем же ключом операции и содержимым
- **THEN** возвращается состояние первой операции; второе изменение данных не выполняется.

#### Scenario: Конфликт содержимого
- **WHEN** с прежним ключом поступает другой код или параметры
- **THEN** возвращается ошибка конфликта без исполнения.

#### Scenario: Сбой исполнителя
- **WHEN** ответ потерян и подтверждённого итога после восстановления нет
- **THEN** состояние unknown сохраняется до сверки; запуск заново не выполняется автоматически и откат не утверждается.

#### Scenario: Истёк срок хранения
- **WHEN** клиент запрашивает удалённый по сроку результат или повторяет просроченный ключ
- **THEN** получает явный result_expired либо отказ просроченного ключа; новый запуск под старым ключом не создаётся. Running/unknown не удаляются автоматически ради квоты.
