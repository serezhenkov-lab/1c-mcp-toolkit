## Purpose

Понятные причины отказов и сведения о готовности подключённого Toolkit.

## ADDED Requirements

### Requirement: Понятная ошибка и сообщения вызова

<a id="rd-01"></a>

Ответ Toolkit SHALL различать запрет Toolkit/proxy, отказ прав 1С, прикладную ошибку, таймаут и потерю связи по источнику, не по словам в тексте. Ответ SHALL содержать ID операции при её наличии, этап, контекст, error=null при успехе либо код/причину ошибки. Сообщения SHALL относиться только к текущему вызову; при невозможности их отделить возвращается явная недоступность без чужого буфера. Секреты не выдаются.

#### Scenario: Ошибка приложения
- **WHEN** ошибка содержит слово «доступ» в имени модуля
- **THEN** она не становится автоматически отказом прав; сохраняются доступные диагностические сведения без секретов.

#### Scenario: Сообщения и успех
- **WHEN** вызов успешно завершён после предыдущего вызова с сообщениями
- **THEN** error=null; выдаются только сообщения текущего вызова либо причина недоступности, прежние сообщения не примешиваются.

#### Scenario: Запрет до исполнения
- **WHEN** proxy отклонил опасную команду до передачи в 1С
- **THEN** объясняется запрет proxy; фиктивный результат выполнения в базе не создаётся.

### Requirement: Состояние подключённой среды

<a id="rd-02"></a>

Toolkit SHALL показывать базу, версию, режим разрешений и готовность со свежестью сведений. Устаревший контакт SHALL не выдаваться за подтверждённое ready. Неопределённый результат перезапуска SHALL не приводить к автоматическому запуску второго клиента.

#### Scenario: Устаревшие сведения
- **WHEN** подтверждённый контакт с исполнителем потерян
- **THEN** показываются disconnected/unknown и время последнего контакта, а не готовность по старому кэшу.

#### Scenario: Ответ перезапуска потерян
- **WHEN** не получено подтверждение завершения restart
- **THEN** состояние проверяется отдельно; второй экземпляр 1С автоматически не запускается.
