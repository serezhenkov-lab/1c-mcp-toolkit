## Что реализовано

- В основной форме вместо прежнего флага — поле deny/ask/session_allow сразу
  после «Формат ответа». Отзыв выполняется выбором ask. Отдельная группа, кнопка,
  пояснение и имя базы удалены по уточнению пользователя. Поле скрывается вместе
  с блоком встроенного сервера в режиме proxy.
- Единый выбор применяется к встроенному MCP, REST и командам существующего proxy.
  Старая настройка false переводится в deny, true — в ask. Автофлаги записи и
  привилегированности больше не обходят выбор основной формы.
- Сохраняются только deny/ask. Отключение, остановка и закрытие сбрасывают временное
  разрешение; startup/restart переносят только старое булево значение deny/ask.
- Разовое решение связано с точным кодом/параметрами, поколением разрешений и
  конкретным окном. Старое окно не подтверждает новую команду с повторным request ID.
- Перед непосредственным исполнением и стартом фонового задания проверяется
  актуальное разрешение. Изменение режима не отменяет уже выполняющуюся команду;
  ожидающая команда не использует отозванное разрешение.
- Сохранён верхний запрет proxy; его существующее сообщение уточнено без нового API.

Отдельный server-host с сохранённым профилем — другой экземпляр исполнения, не
сеанс основной формы. Его профиль и механизм запуска не изменены и не получают
разрешение формы. Это не новая защита от второго чата.
