# Исследование и текущие границы change

## Решение пользователя 12.11.2026

Предыдущий полный охват handoff заменён более узким поручением: первая очередь — три режима разрешений; вторая — поздние результаты и понятная диагностика. Полное покрытие H01–H34 больше не является целью этого change. Старые утверждения о полном покрытии и прежние этапы не действуют. Исторические выполненные исследования сохранены в журнале работы проекта; они не означают реализацию.

| Область handoff / прежнего плана | Новый статус |
| --- | --- |
| Запрещать / спрашивать / разрешить в сеансе | Первая очередь |
| Таймаут, ID, поздний результат, отсутствие автоматического повтора | Вторая очередь |
| Ошибки, сообщения вызова, сведения о базе и готовности | Вторая очередь |
| Изоляция чатов, общий координатор и захват среды | Исключены |
| Ограниченные планы, манифесты, локальная автоматическая и модельная проверка | Исключены |
| Хранилище скриптов, новые транспортные пути, независимые чтения, список с пагинацией, новый API отмены, отдельный стенд прав | Не входят в сокращённый объём |
| Анонимизация | Не входит |

Удалены прежние карточки TASK-001/004/007/008/009 и delta specs chat-isolation/access-testing. Их номера не переиспользуются, last_issued.TASK остаётся 10. Оставлены TASK-003/005/002/006/010 с теми же областями работы и сокращённым составом. Удалённые задачи не объявляются выполненными.

## Исходный механизм до реализации первой очереди

Источники исследованы 11–12.11.2026; рабочая ревизия исследования — 1a78a7a. Новых испытаний в базе при упрощении нет.

- Форма EPF: 1c/MCPToolkit/MCPToolkit/Forms/Форма/Ext/Form/Module.bsl:25469–25479 — execute_code сначала проверяет опасные слова и автофлаги, затем флаг РазрешатьОпасныеОперацииСПодтверждением. На ревизии 1a78a7a флаг означает «отклонить / спросить», а не «спросить / разрешить всё».
- Та же форма:2453 — ВсеОперацииАвтоРазрешены; на ревизии 1a78a7a авторазрешения записи и привилегированности могут пропускать диалог. При новом явном deny/ask эти исключения не должны его обходить.
- README_FULL.md:239–263 объясняет danger_confirm и отличие proxy. onec_mcp_toolkit_proxy/config.py:39–42 и mcp_handler.py:674–703 — proxy либо запрещает опасную команду, либо передаёт requires_approval. Флаг формы не отменяет его запрет.
- onec_mcp_toolkit_proxy/command_queue.py:444–477 — wait_for_result очищает состояние в finally, включая timeout. Ранее изолированная проверка очереди подтвердила потерю позднего ответа; это не runtime-тест базы.
- onec_mcp_toolkit_proxy/file_transport.py:65–89 — один active до достоверного ответа, без автоматического повтора. Этот инвариант не отменяется ради новой настройки.
- Диагностика и readiness опираются на действующие ответы/регистрацию runtime; конкретные методы отделения сообщений 1С ещё должны быть проверены.

## Предпосылки после сокращения

Проверка от 11.11.2026 обнаружила для 1599050 прямой встроенный HTTP на 6003, а отдельную установленную proxy-систему с файловыми каналами — на 6004. Тогда сверены хеш установленного EPF и четыре файла proxy с манифестом; это не доказывает, какой EPF сейчас открыт в 1С. Настройки и состояние не перепроверялись 12.11 при редактировании спецификации.

Ранее рекомендованный отдельный HTTP proxy-стенд был частью более широкой архитектуры и больше не обязателен. Для первой очереди достаточно существующей формы/встроенного HTTP; другие уже поддержанные пути учитываются в совместимости. Новые среды и подключения автоматически не создаются.

Различимость чатов не доказана, но больше не требуется: режим общий для сеанса обработки. Серверные MCP-сессии и chat_id не используются как новые границы разрешения.

BSL прочитан через RLM по точным путям; EPF не поддержан индексом CF/EDT. В форме обнаружены 344 BEGIN GENERATED, в ObjectModule.bsl — три крупных GENERATED-блока. В затронутые области входят авторазрешения и планировщик. Генератор/шаблоны не найдены в форке и полном публичном дереве upstream ca14a98; появление маркеров связано с 704d7a4. Harness install.ps1 вызывает сборщик EPF из готовых XML/BSL, а не этот генератор. До правок необходимо установить поддерживаемый способ синхронизации копий; самостоятельно считать одну из них первичной нельзя.

Ранее штатные тесты в выбранном Python не запустились из-за отсутствия ahocorasick. Это не доказательство несовместимости Python; окружение для будущих проверок требуется подготовить без изменения работающей установки.

## Реализация первой очереди 12.11.2026

После отдельного поручения пользователя создана ветка `codex/session-approval-modes`.
Режимы реализованы в рукописных обработчиках основной формы; все 344 GENERATED-блока
и модуль объекта сохранены без изменения. Дублированные ядра не объявлялись первичным
источником, генератор не восстанавливался. Для этих правок препятствие снято обходом
генерируемых участков, а не предположением об их происхождении.

Отдельный server-host использует собственный профиль вне сеанса основной формы;
его прежние правила не изменены. Первая очередь работает на существующих путях
основной формы, не внедряет новый транспорт. Сверены исходная ревизия 1a78a7a,
платформа 8.3.27.2342 и новая пустая тестовая файловая база.
Проверки, исправления тестовой обвязки и оставшаяся приёмка — в [протоколе](verification.md).
Работающая установка не обновлялась. На момент проверки первой очереди вторая ещё не выполнялась. Последующим поручением 12.11.2026 её реализация разрешена; результаты фиксируются отдельно от этого исторического протокола.


## Упрощение формы после первой сборки

По уточнению пользователя удалены отдельная группа режима, пояснение, имя базы и кнопка отзыва. Поле перенесено после «Формат ответа», точно на прежнее место флага. Пользователь явно выбрал это размещение с учётом скрытия блока в режиме proxy. Отзыв выполняется выбором ask; тесты используют обработчик изменения поля. Механизм трёх режимов и вторая очередь не изменены.
