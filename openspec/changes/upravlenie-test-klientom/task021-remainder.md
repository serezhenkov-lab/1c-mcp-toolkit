## Остаток после MVP и по потребности прикладного пилота

- Причина editing/property_read_failed и положительные ветви таблицы/табличного документа проверены; повторно их не назначать. Остаются другие типы полей (числа/даты/ссылки), новые формы/среды. Обычное поле ввода не предоставляет проверенный Boolean editing: фокус/текст не заменяют его; положительное требование остаётся открытым.
- При переносе на файловый мост: доступ свежего test_session/status и binding при открытом подтверждении. Сейчас provider.recover получает context_observation_timeout (status остаётся queued за awaiting_approval). После решения recovery работает; HTTP/embedded работают и во время ожидания. Это не блокер встроенного HTTP MVP. Старый контекст не подставлять, проверки привязки не ослаблять, мутацию не повторять. Принятые ветви повторно не назначать без нового риска.
- Бизнес-сверка unknown без operation_id и проверяемое явное решение о продолжении. Текущая остановка безопасна, но не заменяет эту реализацию; неизвестная мутация не повторяется.
- Другие реальные профили uilog/форм — только при наличии соответствующего примера и отдельного ревью; нынешние артефакты не доказывают БСП-формы по аналогии.

- Пункт 1.4 и Открыть() значения ячейки остаются открытыми; публичная e1cib-навигация не закрывает этот пункт.
- Рабочая установка не обновляется. Редактор политик не добавлен и не объявляется обязательным остатком без требования.

Подтверждённые наборы повторно не назначать. Неполнота среды, deferred-зависимости и безопасный отказ не считаются завершением положительного требования.
