# Проверки перед реализацией — 12.11.2026

## Результат

Исследовательские пункты TASK-011/1.1 и 1.2 выполнены: BSL-зависимости выделены и скомпилированы, штатный API проверен в отдельном стенде. На **8.5.1.1529 — 32 из 32 проверок успешны**. Без `/TESTMANAGER` создание `ТестируемоеПриложение` отклонено платформой, как ожидалось. Код и работающая установка Toolkit не изменялись.

На 8.3.27.2342 успешны 28 из 32 проверок. Отсутствует `ПолучитьТекущуюСтроку()`; после выбора значения не подтвердилось чтение исходного поля, затем не прошли навигация и закрытие. Последние три результата не доказывают отсутствие соответствующих API: состояние UI после выбора требует отдельного разбора. Полная совместимость 8.3 не объявляется. Проверенная исходная платформа для реализации — 8.5.1.1529; поддержка иных версий требует отдельного подтверждения.

Это проверка предпосылок и отдельных платформенных операций. Интеграция `test_*`, бизнес-сценарий с записью документа, HTTP/file, клиент-серверная база, снимки и восстановление владения после перезапуска ещё не реализованы и не приняты. Пункт 1.3 о схемах команд остаётся открытым.

## Выводы для адаптации

1. **Зависимости:** [138 функций](bsl-dependencies.md), 28 входов, две переменные, два адаптера. Исходники Answer42 извлечены без реализации его транспорта. Сборка проверяет замыкание локальных вызовов, но не существование поздно связываемых методов UI.
2. **Таблица:** `ПолучитьСтроки()` отсутствует на обеих проверенных платформах. В 8.5 подтверждён `ПолучитьТекущуюСтроку()`, в 8.3 — нет. `ПолучитьВыделенныеСтроки()` работает после явного выделения всех строк: это изменение UI, а не чистое чтение. При `allow_navigation=false` такой обход использовать нельзя; возвращать неполноту/недоступность. Тестовая таблица мала; полнота больших и динамических списков этим не доказана.
3. **Имена колонок различаются:** для `ПерейтиКСтроке` в стенде нужен ключ данных `Ключ`, для `ПолучитьТекстЯчейки` — имя элемента `СтрокиКлюч`. Контракт должен различать эти адреса.
4. **Ввод:** вызывать `Активизировать`, вводить текст и явно завершать редактирование до проверки. Пустой `ВвестиТекст("")` в первоначальной пробе сохранил прежнее значение; отдельный `Очистить()` подтвердился. Не заменять отсутствие исключения доказательством изменения.
5. **Окна:** в части запусков 8.5 активное окно было `Неопределено` при наличии окна в списке. Явный объект окна оставался пригоден. Это наблюдение конкретного стенда с фоновым запуском, не утверждение о всех сеансах 8.5. Выбор `active` должен возвращать понятную ошибку, а не автоматически подставлять первое окно.
6. **Страницы:** для проверенной страницы работает `Активизировать()` с чтением `ПолучитьТекущуюСтраницу()`. `Нажать()` на скрытом содержимом страницы вызвал ошибку видимости. Метод выбирать до действия, без цепочки повторных мутаций.
7. **Сообщения:** закрытая панель даёт ошибку недоступности метода; это не пустой список. После явного отказа тестовой формы сообщения читаются без закрытия панели. Проверка отказа формы не является проверкой транзакционной записи документа.
8. **Предупреждения EPF:** изменение файла вызвало предупреждение безопасности; `/DisableStartupDialogs` его не снял. Подтверждено [журналом регистрации](evidence/external-processing-warning.txt). Для автоматического стенда нужен заранее настроенный отдельный тестовый пользователь. Указанная пользователем настройка защиты проверена; механизм описан в [руководстве 1С](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.22_Developer_Guide/Appendix_6._System_behavior_specifics_in_different_modes/6.10._Unsafe_action_protection/6.10.2._Disabling_the_unsafe_action_protection/?language=en). Будущий Toolkit не должен сам отключать защиту в произвольной базе.

## Достоверность и ограничения

Первоначальные неуспешные пробы сохранены в [протоколе](evidence/runtime-result-initial.json). Ошибки проверочного сценария исправлялись отдельно от подтверждённых ограничений API. Пользователь сообщил об одном ручном нажатии «Да», не запомнив текст окна; этот запуск и запуски с тайм-аутом не входят в итоговые успешные 32/32. После настройки `ApiProbe` итоговый прогон прошёл без ручных действий. Computer Use только попытался прочитать окно, не выполнил ни одного действия сценария; далее не использовался.

Перенос всех ветвей Answer42, UI-ID, уникальность селекторов, точные дедлайны, восстановление после аварии, запрет повторов, stop после перезапуска, скриншоты, анонимизация и оба транспорта остаются задачами реализации/приёмки. Вспомогательные Python-серверы и протоколы доноров не запускались. Изменения в коде Toolkit, присутствующие в рабочем дереве из другого чата, этой проверкой не затрагивались.
