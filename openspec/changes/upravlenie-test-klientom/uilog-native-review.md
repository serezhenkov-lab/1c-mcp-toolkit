# Свежий uilog и ревью 11.2 — 17.11.2026

**Новая запись получена на 8.5.1.1529; текущий импорт заблокирован, полноценный черновик не создан.** Проверка выявила расхождение синтетического профиля XML с реальным журналом платформы. Это отрицательный результат проверки совместимости, не завершение 11.2. Исходные требования и открытые отметки сохранены.

## Получение записи

Отдельная копия подготовленной файловой базы, ApiProbe, HTTP proxy из checkout, тонкие клиенты Windows, платформа 8.5.1.1529. В **копию** EPF менеджера добавлены только две экспортные функции, вызывающие штатные методы `ТестируемоеПриложение.НачатьЗаписьЖурналаДействийПользователя()` и `ЗавершитьЗаписьЖурналаДействийПользователя()`. Методы и возвращаемая строка подтверждены контекстом платформы 8.5. Диагностическая EPF прошла сборку с ThinClient/Server/HandlersExistence; производственные BSL и импортёр не менялись. Это функции существующего менеджера, не наблюдатель в клиенте.

Нативная форма создания T43_Required открыта до записи. В интервале записи выполнен один публичный test_input/text в ОбязательноеПоле с уникальным тестовым текстом. Запись получена штатным рекордером платформы от автоматизированного действия, **не имитацией XML и не ручным вводом человека**. Запись документа не выполнялась. Исходные 9 документов по выбранным полям совпадают до/после, все три собственных процесса завершены; несохранённая форма осталась только в завершённой тестовой сессии.

## Фактический формат и результат импорта

Записаны три события в двух последовательных блоках окна:

1. `FormField name=ОбязательноеПоле / activate`.
2. То же поле / `inputText text=...`.
3. `FormField name=Номер / activate` — завершение редактирования переводом фокуса.

Окно имеет **caption**, а не ожидаемый импортёром title. У вложенной Form есть title. Второй заголовок содержит ` *`: это наблюдённое изменение состояния несохранённой формы. Объявлен префикс пространства имён `d1p1`, сами элементы XML непомеченные; причиной отказа namespace в этом прогоне не являлся.

[Исходный import-report](evidence/uilog-native/import-report.json): status=blocked, draft=null, candidate_steps=[], dispatch_count=0, execution_ready=false. Две unknown_attribute относятся к caption. Дополнительно ambiguous_recorded_target — ложная диагностика для этих блоков: импортёр сравнивает name/title, оба отсутствуют у ClientApplicationWindow, и не использует различные caption. Ни одна из этих ошибок не доказывает неоднозначность живых целей.

Для локализации **без новой записи и без изменения импортёра** сделана явно помеченная [диагностическая копия](evidence/uilog-native/diagnostic-caption-only.xml): только caption → title, порядок и события сохранены. [Её результат](evidence/uilog-native/diagnostic-import.json) — всё ещё blocked/draft=null; появился один кандидат test_input/text и два unsupported_event_target на активизациях полей. Значение вынесено в отдельный параметр. Диагностическая копия не выдаётся за сырой журнал или успешный импорт.

## Ревью

[Сохранённый отчёт ревью](evidence/uilog-native/uilog-review.json) сопоставляет оба caption и поля с деревьями, полученными непосредственно до/после записи. В соответствующем снимке каждая форма/цель найдена ровно один раз; имя, подпись, тип, enabled/read_only согласованы. Это проверка этих снимков, не гарантия будущей однозначности или стабильности ID. Смена title и зарегистрированных ID после редактирования видна в артефактах и не скрыта.

Кандидат ввода сохраняет данные отдельно от шаблона. В нём нет переносимого разрешения/базы/сеанса. Но полный журнал не представим текущим контрактом: отдельного test_action для активизации поля нет. ActivateWindow не эквивалентен активизации поля. Возможность поглотить activate как часть составного ввода требует явного правила сопоставления и доказательства эффекта; произвольно удалять первое/последнее событие нельзя.

**Решение ревью: blocked.** Исходник и все события сохранены, supported prefix не объявлен полным сценарием. draft=null не заменён ручной установкой reviewed. Импортированный сценарий не запускался; полный runtime-preflight на отсутствующем draft не имитировался.

## Следующий конкретный остаток

1. Поддержать подтверждённый профиль ClientApplicationWindow/caption и исправить определение неоднозначности последовательных блоков записи. Не считать всякое повторение цели новым дублирующим UI-элементом.
2. Определить в контракте точное преобразование активизаций полей: явное действие либо доказанное поглощение составным test_input с проверяемыми условиями. Не ослаблять запрет потери событий/альтернативного действия.
3. После соответствующих изменений повторно импортировать **этот сохранённый XML**, проверить новый результат и завершить ревью. Повторная запись/старые синтетические наборы без зависимых изменений не требуются. Новый UI-прогон нужен только если правило требует дополнительного наблюдения.
