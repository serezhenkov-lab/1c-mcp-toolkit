### Состав и границы

Windows, тонкий клиент **8.5.1.1529**, одна доступная тестовая файловая база, один менеджер и один тест-клиент. Связь: агент → HTTP/MCP встроенного сервера Toolkit → штатный TestManager API → клиент. Профиль задаётся и сохраняется штатными средствами Toolkit; рабочий запуск не зависит от tests/, ручной правки BSL или временных файлов предыдущих прогонов. Используются существующие штатные компоненты обработки, без нового наблюдателя/адаптера.

**Охват определяется действиями, а не видами метаданных.** Документы, справочники, обработки, отчёты, регистры, константы, настройки и общие формы входят как области применения. Отсутствие поддержки отдельного действия в таблице не исключает весь регистр или справочник. Не обещается наличие формы/команды, которой нет в конфигурации или которая недоступна текущей роли.

Обязательны: подключение/start или attach по профилю, status и завершение собственного клиента; навигация по разделам, меню и командам панелей; открытие/переключение/закрытие форм и вкладок; чтение доступных полей, текст/число/дата/флажок/однозначный список; кнопки, предусмотренные диалоги и явный ответ; сохранение/отмена изменений, запуск обработки и формирование отчёта; чтение доступного результата, query-сверка сохранённых данных, сообщения и снимок именно клиента. Режим ask и явный отказ/разрешение сохраняются, скрытого авторазрешения нет. Навигация по меню проверяется непосредственно, а не подменяется e1cib-ссылкой.

### Один пакет приёмки с представительными формами

1. Из комплектного кандидата, без тестовых модификаций EPF, настроить профиль штатным способом и подключить клиент. Получить живой status и дерево нужной формы через прямой endpoint обработки.
2. Пройти настоящий раздел/меню/команду панели до формы; по одному короткому примеру проверить карточку справочника, документ, обработку, отчёт, предусмотренную форму регистра, константу и настройки/общую форму. Один набор данных и один комплект, без отдельной полной регрессии на каждый вид объекта. Если примера нет в текущем стенде, подготовить его только в изолированной тестовой конфигурации; рабочую конфигурацию не изменять.
3. Запись проверить на документе и элементе справочника через UI и HTTP-query; константу/настройку — сохранить, переоткрыть и проверить сохранённое значение, затем восстановить исходное. Для обработки проверить наблюдаемый результат команды; для отчёта — параметры, формирование и доступный текст/значения результата плюс снимок. Для регистра — открыть форму, прочитать доступное и подтвердить данные запросом; запись через предусмотренную отдельную форму допустима, адресация одинаковых строк не подменяется текстовым совпадением. T43_Required остаётся одним из технических эталонов, а не границей MVP. Прикладной пилот оценивается отдельно от вывода совместимости по аналогии.
4. Для уже вызванной записи повторная доставка того же request_id не вызывает повторное нажатие; при потере подтверждения/unknown агент останавливает мутации и сверяет существующую операцию/базу. При отказе пользователя действие не вызывается. Ранее подтверждённые случаи засчитываются по совместимой версии; повторяется только затронутый изменениями риск.
5. Закрыть форму и завершить только собственный клиент; профиль должен сохраняться. Тестовые данные убирать только по полученной точной ссылке в выделенной базе, не по широкому поиску. Очистка является частью стендовой проверки, не автоматической командой удаления в прикладной работе.

**Готовность MVP** — комплект запускается без harness, пакет выше даёт проверяемые результаты, обязательные действия доступны, ограничения перечислены для конкретных действий/видов элементов, а не как запрет класса объектов. Рубеж подтверждён на указанной файловой 8.5.1.1529: [протокол и границы](http-mvp-verification.md). Это не полная приёмка v1/TE. Дополнительные проверки назначать только по блокеру пакета или изменению кода; не запускать заново всю матрицу. [Историческая оценка остатка MVP](estimate.md).

**После MVP:** прикладной пилот и исправления по реальным случаям → перенос на файловый мост (включая queued status/binding при awaiting_approval) → остальные среды/возможности. Python proxy, полный импорт uilog, отдельный runner и его расширенное восстановление, unknown без operation_id с автоматизированным решением, сложные таблицы/карточки/Открыть(), diff/метрики и полная матрица сред не блокируют MVP. Уже работающие функции сохраняются. Анонимизация отложена, подключение наблюдателя не разрешено. Безопасная остановка при неизвестном исходе остаётся обязательной.

Конкретные ограничения: изменение/выбор строк без доказанной независимой идентичности, табличный выбор ссылочного значения на таком основании, click_group карточки и открытие значения ячейки, Boolean editing обычного поля, полный структурный разбор произвольного MXL. Они отражаются в доступности команды и ошибке; меню/разделы/обычные настройки исключением не являются. При невозможности обязательной навигации нативным API рубеж и оценка пересматриваются с пользователем, а не принимаются молчаливым исключением.
