# 1c-mcp-toolkit / TASK-014 — Ввод значений и действия с формами

## Цель и ожидаемый результат

Выполнять ввод и действия с проверкой результата и явной обработкой модальных окон.

## Требования и сценарии

[UI-03, UI-04](../specs/test-client-ui/spec.md), [TI-03](../specs/test-client-integration/spec.md); ввод, форма выбора, отказ значения, отказ записи и модальное закрытие.

## Границы работы

Текст/число/дата, флажок, список/форма выбора, кнопка, окно, страница и закрытие формы. Для согласованного MVP добавлен 4.5: нативная навигация разделы/меню/команды панелей; готовая адресация/coverage из TASK-018/8.2 переиспользуется, здесь реализуются вызов, проверка разрешения и результата. Ограничения по действию, не по принадлежности формы документу/справочнику/регистру/константам/настройкам/обработке/отчёту. Не выбирать ответы на диалоги автоматически. Табличный выбор без доказанной идентичности остаётся открытым.

## Затрагиваемые объекты и технические указания

Служебная форма, адаптированные функции ввода/выбора Answer42 и существующая проверка разрешений. См. [решение](../design.md) и [исследование](../research.md).

## Зависимости

Завершённый [TASK-013](TASK-013.md). Остаток 4.1 по табличной форме выбора требует доказанной идентичности [TASK-019](TASK-019.md) и чтения/поиска 5.1. Пункт 4.4 отдельно зависит от 1.4 и проверки признаков карточки/гиперссылки до нажатия; готовность строк этих признаков не доказывает.

## Критерии приёмки и проверка

После ввода прочитано фактическое значение; неоднозначный или неполный выбор не выполнен. При неизвестном исходе нет цепочки альтернативных мутаций; сбой диагностики не вызывает повтор действия. Нажатие записи с ошибкой заполнения не выдаётся за запись. Закрытие формы с вопросом возвращает диалог.

## План выполнения

Прогресс хранится только в [tasks.md](../tasks.md#task-14).

- 4.1 Реализовать test_input и завершение редактирования; проверить текст, флажок, полный и неоднозначный выбор, отклонённое значение и отсутствие альтернативного ввода при неизвестном исходе.
- 4.2 Реализовать test_action и возвращаемое состояние; проверить кнопку, окно/страницу, модальное закрытие и сбой диагностики после вызванного действия без его повтора.
- 4.3 Подключить проверку разрешений перед действиями и разделение execution/verification; проверить deny, ask, session_allow и отказ записи обязательного поля.

- 4.4 Реализовать click_group по подтверждённой capability; проверить карточку-гиперссылку, обычную группу, отказ версии и отсутствие повторного нажатия.
