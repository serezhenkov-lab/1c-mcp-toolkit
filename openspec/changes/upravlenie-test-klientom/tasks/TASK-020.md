# 1c-mcp-toolkit / TASK-020 — Сверка бизнес-результата с эталоном

## Цель и ожидаемый результат

Сравнивать результаты разрешённых запросов и подтверждённых UI-наблюдений с явным эталоном.

## Требования и сценарии

TE-03. Дополнение к TI-05, не условие исходной приёмки: существующий итоговый запрос остаётся допустимым. См. [дополнительные требования](../specs/test-client-testing-extensions/spec.md), [UI](../specs/test-client-ui/spec.md), [сеанс](../specs/test-client-session/spec.md) и [интеграция](../specs/test-client-integration/spec.md).

## Границы работы

**Добавлена в план 15.11.2026; последующими поручениями 16.11 разрешены контракт 10.1, реализация 10.2 и доступная часть 10.3.** Компаратор полученных данных; без нового запроса-шлюза и переноса донорского попарного сходства строк. Первой поддержать результаты имеющихся запросов. UI-интеграция остаётся обусловлена доказанным охватом/идентичностью.

## Затрагиваемые объекты и технические указания

Существующие модели результатов/query и тестовый harness; конкретный модуль и дополнительный API определить в 10.1. Подписи, значения и diff проходят текущую обработку данных, технические ID сохраняются. Основание: F-19 в [реестре](../donor-findings-register.md), [сводный разбор](../donor-synthesis-roadmap.md), [решение](../design.md).

## Зависимости

Очередь 1 (6.1–6.3 и сквозное восстановление 2.3) — до продуктовой интеграции. Контракт можно уточнять раньше. Разработка на query-данных независима от TASK-019/5.1; подключение UI-таблиц требует доказанного охвата и целостности из 5.1. Сводная последовательность — [план](../tasks.md).

## Критерии приёмки и проверка

Проверены схема/типы, порядок, ключи, дубли, missing/unexpected/changed, явные исключения и ошибка источника. Итоговый запрос в той же базе подтверждает ровно один объект; частичный набор не доказывает полную таблицу. До реализации проверить схемы/контракт; при реализации отдельно фиксировать статические проверки, сборку, runtime и приёмку, не расширяя охват старых протоколов.

## План выполнения

Прогресс хранится только в [tasks.md](../tasks.md#task-20).

- 10.1 Закрепить контракт эталона и сравнения: схема, типы, порядок, ключи, кратность, исключения и источник/охват; проверить примеры отличий и недоступных данных.
- 10.2 Реализовать сравнение результатов существующих запросов со структурированным diff; проверить дубликаты, пропуски, лишние строки, типы и отказ запроса без ложного равенства.
- 10.3 Подключить сравнение к проверке бизнес-результата, а UI-наборы — только при доказанной целостности/охвате; проверить один документ в той же базе и ограничения частичного снимка.

## Результат и доказательства

Один ранее созданный через UI документ подтверждён свежим запросом по независимому эталону; новая UI-запись не повторялась. Итоговый пакет 7/7 (4 свежие проверки 1С и 3 локальных защитных случая), новые unittest 6/6. UI-наборы, полный новый сквозной цикл и прочие среды остаются открытыми. Рабочая установка не обновлялась, отметки 13/42 сохранены.

16.11.2026, последующий этап: [10.2 реализован и локально проверен](../query-comparison-implementation.md). Чистый Python-модуль нормализует структурированные query-ответы и сравнивает три режима, формируя ограниченный diff без потери глобальных счётчиков. 17 тестовых методов, включая все 24 примера контракта, прошли. Новых runtime-прогонов нет; 10.3 и полная приёмка открыты. Формальные отметки сохранены.

16.11.2026: закреплён [контракт v1 для 10.1](../query-comparison-contract.md): локальный API будущего компаратора/нормализатора, типизированный эталон, привязка источника, полнота, bag/keyed/ordered, кратность, исключения и ограниченный diff. Разобраны 24 примера ожидаемого поведения, включая отказы, предел выборки и потерю типов при сериализации. Это ручная проверка контракта, не тесты реализованного компаратора и не новый прогон 1С. Существующие публичные API не изменены. 10.2/10.3 не выполнены; незавершённые отметки плана сохранены. Донорский анализ и прежние прототипы не засчитаны как выполнение.
