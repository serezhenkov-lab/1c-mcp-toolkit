## Результат локального пакета

**8.2 — реализовано:** вместо постоянного safe_list_state_api_unverified читается `ВыпадающийСписокОткрыт()`/DropListIsOpen у расширения тестируемого поля ввода. Доступный MCP-индекс базового типа метод не содержал; он найден в сохранённой справке установленной 8.5.1.1529 и подтверждён runtime: false → true → true → false → false. Перед вызовом проверяется `ВидПоляФормы.ПолеВвода`. На флаге нативный метод тоже возвращал false, хотя расширение документировано для input field; публичный результат теперь явно `unavailable/not_an_input_field`. Ошибка чтения остаётся `property_read_failed`.

Публичный inspect при открытом/закрытом списке возвращает правильный boolean и сохраняет штатные open/text/value до/после чтения. Список не закрывается и значение не выбирается. Наблюдателя в клиенте нет: тестовые экспорты только в отдельной EPF менеджера, для подготовки и независимого чтения состояния fixture.

**8.3 — подтверждено новым сценарием:** отсутствующая цель до действия даёт errors.command, observation=null и отсутствие last_confirmed_step. После одного успешного нажатия отказ изображения не меняет исходные diagnostics/operation_id; повтор исходного request_id не увеличивает счётчик. После завершения клиента сохранённые артефакты операции доступны из общего журнала.

**6.4 — новые отрицательные проверки:** свёрнутое, скрытое и закрытое окно не возвращают PNG и не подменяются менеджером. Скрытие/восстановление на стенде приводит к потере ready тестового соединения; для последующего независимого чтения счётчика harness явно выполняет attach к тому же существующему клиенту. Новый процесс/документ не создаётся. Бесшовное сохранение соединения не объявляется успешным. Снимки не поднимают окна автоматически.

## Уточнение HWND после отдельной проверки

[hwnd-check.md](hwnd-check.md): в каждом сеансе логическое основное окно одно; main+штатное оповещение дают два настоящих видимых unowned HWND одного PID. На Такси и Версия 8.5 подтверждён отказ снимка без PNG и CREATE/DESTROY с новым HWND следующего оповещения. Эта неоднозначность больше не является непройденным локальным сценарием. Пересоздание именно основного HWND не воспроизведено: ОбновитьИнтерфейс сохраняет HWND, смена режима после начала работы запрещена платформой. Этот предел доказательств сохраняется; 6.4 не закрыт.
