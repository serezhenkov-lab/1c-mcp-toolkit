# Инфостарт: дополнительные примеры управления тест-клиентом

Дата: 14.11.2026. Продолжение исследования доноров. Выбор для внедрения остаётся отложенным; код Toolkit не менялся. Публикации Инфостарта не исключены из исследования. Ниже отделены опубликованные примеры, прочитанные исходники и недоступный материал.

## IS-01. Менеджер внешних отчётов и обработок в нескольких базах

[Публикация с кодом](https://infostart.ru/1c/articles/1231390/), 15.05.2020. Код доступен прямо на странице, запрашивать вложение у пользователя сейчас не требуется. Автор указывает платформу 8.3.16.1224 и несколько конфигураций.

Полезный кандидат F-17 — матрица различий интерфейса: «Обновить из файла» / «Загрузить из файла», предупреждение при первой загрузке и повторная загрузка после него, разные диалоги закрытия. Это материал для наших проверок совместимости и распознавания ожидаемого состояния.

В опубликованном примере есть запуск `/TESTCLIENT`, ожидание подключения, выбор основного окна, поиск строки по наименованию и обработка диалогов БСП. В цикле подключения не показана пауза. Выбор по наименованию не доказывает уникальность строки. Код содержит видимые опечатки (`озврат`, `НайтиОбъек`); готовность к выполнению не подтверждена.

Для Toolkit полезнее сценарии и ожидаемые переходы интерфейса. Автоматические ответы на предупреждения безопасности и закрытия нельзя переносить как универсальное поведение. Современные версии БСП этим материалом не проверены.

## IS-02. Минимальный ui-driver из публикации про Claude Code и EDT

[Публикация](https://infostart.ru/1c/articles/2815822/) ведёт к открытому [репозиторию](https://github.com/konstmax1388/claude-code-1c-edt/tree/7c5d53af03e738f1f34d6b0b1c8e665b46edf884/ui-driver). Зафиксирован commit `7c5d53af03e738f1f34d6b0b1c8e665b46edf884`, локально `.local/donors/claude-code-1c-edt`. В корне MIT LICENSE; конкретные заимствования и атрибуцию проверять при выборе. BSL прочитан через RLM как текст: нестандартная структура не даёт основания для выводов по индексу метаданных.

Подтверждено исходниками:

- [Модуль формы, строки 9–35](https://github.com/konstmax1388/claude-code-1c-edt/blob/7c5d53af03e738f1f34d6b0b1c8e665b46edf884/ui-driver/src/ui_Драйвер/Forms/Форма/Ext/Form/Module.bsl#L9): параметры двух файлов передаются через `/C`, одноразовый обработчик ожидания запускает исполнение после открытия формы. Чтение и `Выполнить()` находятся в `&НаКлиенте`; затем результат пишется в файл и менеджер завершает работу.
- [Дамп, строки 44–67](https://github.com/konstmax1388/claude-code-1c-edt/blob/7c5d53af03e738f1f34d6b0b1c8e665b46edf884/ui-driver/src/ui_Драйвер/Forms/Форма/Ext/Form/Module.bsl#L44): рекурсивный вывод типа, имени и заголовка через `ПолучитьПодчиненныеОбъекты()`, глубина по умолчанию 5. Ошибки чтения свойств и потомков подавляются; остановка по глубине не отмечается в выводе.
- [Пример открытия формы](https://github.com/konstmax1388/claude-code-1c-edt/blob/7c5d53af03e738f1f34d6b0b1c8e665b46edf884/ui-driver/examples/03_open_form_dump.bsl#L1): подключение к localhost:1538, выбор основного окна, поиск команды по типу/заголовку, нажатие, поиск формы с таймаутом 20 и дамп глубины 3. Это пример с заполнителями, а не общий resolver; при исключении финальное отключение не гарантировано.
- [PowerShell, строки 1–9](https://github.com/konstmax1388/claude-code-1c-edt/blob/7c5d53af03e738f1f34d6b0b1c8e665b46edf884/ui-driver/ui.ps1#L1): каждый вызов запускает отдельный менеджер в `tm-base`, ждёт его завершения и при таймауте завершает полученный процесс. Путь к платформе задан жёстко. Вывод — текст, файл результата читается с подавлением ошибки отсутствия; ошибки BSL не преобразованы в отдельный статус shell.

F-18: компактный пример клиентского исполнителя и отдельной базы менеджера пригоден как справочный прототип для воспроизводимой диагностики. Сам принцип уже присутствует в нашем направлении; это не самостоятельный новый компонент для переноса. Полезно сохранить минимальный набор зависимостей и последовательность «подключение → наблюдение дерева → адресное действие».

Ограничения: нет идентификатора операции, дедупликации, атомарной публикации результата и постоянной сессии; ошибки/успех смешаны в тексте. В показанном коде нет проверки владения тест-клиентом. Таймаут менеджера не доказывает, что действие в тест-клиенте не выполнено. Для нашего снимка нужны признаки обрезки и отказов чтения. README предлагает исключение из защиты опасных действий и отдельный запуск клиента через WMI — это рекомендации автора, не проверенные и не применённые нами.

## IS-03. 1С:Сценарное тестирование 3.0

**Продолжение 15.11.2026:** пользователь предоставил полные XML/BSL-выгрузки Сценарного тестирования 3.0.40.7 и Тестировщика 1.0.10.34. [Исследовано общее ядро и различия](1c-testing-products-source-analysis.md). Прежний запрос EPF ниже закрыт предоставленными исходниками; повторно запрашивать его не требуется. Ниже сохранена граница первоначального исследования 14.11.2026.

[Публикация о записи и отладке](https://infostart.ru/1c/articles/697079/) относится к другому продукту, чем уже разобранный TestingTool-3. Повторный доступ в этом интервале вернул HTTP 429; это ограничение запроса, а не подтверждение платного доступа. Исходники обработки по этой публикации не исследованы.

Адресный запрос пользователю: если доступен этот продукт, предоставить EPF менеджера сценарного тестирования, экспортированный командой «Сохранить обработку в файл», либо его текстовую выгрузку. Нужны реализация записи/преобразования событий в сценарий, адресация элементов и ожидания. Сама статья не заменит исходники. Если обработки нет, оставить пункт открытым без требования покупать материал.
