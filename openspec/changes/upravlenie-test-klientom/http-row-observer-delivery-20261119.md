19.11.2026. Windows, тонкий клиент 8.5.1.1529, отдельная файловая каркасная база. Управление 1С выполнено зарегистрированным `toolkit-carcass-85`. Для проверки обычной EPF использован порт 17825 и привязка к 127.0.0.1.

Для запуска одной пробы фикстура получает ID из локального файла. Запрос пробы, снимок и подтверждение передаются по HTTP. Штатное включение клиентской роли и автоматический запуск проб остаются отдельной работой.

## Доставка и очередь TestManager

Менеджер резервировал пробу при свободном TestManager. Действие, принятое во время резерва, оставалось в очереди до подтверждения пробы или срока её ожидания. На стороне клиента снимок собирался один раз и сохранялся для повторной отправки с тем же ID.

- Фикстура намеренно отбросила первую выдачу после HTTP 200. Вторая выдача вернула тот же ID. Трасса показала две выдачи, один снимок и одно принятие результата. Вызов чтения таблицы ожидал с `execution=not_started`, после подтверждения пробы прошёл за 172 мс выполнения драйвера.
- Две команды «Перечитать» прошли после подтверждений своих проб. Добавление строки, ранее воспроизводившее тайм-аут при непрерывном опросе, также прошло после подтверждения. Драйвер выполнил добавление за 272 мс, оба значения подтвердились. Следующее чтение показало ровно одну добавленную строку и три строки в форме.
- В четырёх положительных случаях от назначения до подтверждения пробы прошло 9,96–13,83 с. Этот интервал включает постановку команды, управление тестом и передачу пробы. Время драйвера измеряется отдельно после ожидания.
- Для пробы без сигнала клиенту `take` и `reply` отсутствовали. Через 18 секунд резерв истёк и поставленное в очередь чтение окон завершилось успешно. Выполнение драйвера заняло 18 мс.

Это проверка разделения работы на тестовом стенде. Резерв даёт ограниченное ожидание очереди. Применимость штатной координации к другим сеансам и сценариям ещё открыта.

## Перечитывание источника на одной накладной

В отдельной базе создана синтетическая приходная накладная `000000001`, UUID ссылки `5b669d34-e3e6-11f1-bb22-88f4dac657c2`. Через MCP сохранённые строки того же документа заменены с A на B. Форма оставалась открыта с UUID `1884c6f7-3c15-42e7-961f-501e517459b1`.

| Проба | Количество / цена в форме | Нативные ID | Сравнение коллекции с предыдущей |
| --- | --- | --- | --- |
| Исходное открытие A | 2 / 3, 5 / 7 | `[0, 1]` | исходный снимок |
| Запись B в базе до перечитывания | 2 / 3, 5 / 7 | `[0, 1]` | `equal` |
| Первое «Перечитать» | 11 / 30, 12 / 40 | `[0, 1]` | `equal` |
| Повторное «Перечитать» тех же данных | 11 / 30, 12 / 40 | `[0, 1]` | `equal` |

После перечитывания ID `0` и `1` относятся к новым строкам при прежнем UUID формы и результате сравнения `equal`. Для актуальности токена требуется независимый признак поколения источника. Сигнал контролируемого перечитывания доступен как действие TestManager. Автоматический отзыв токенов, включая изменения вне TestManager, остаётся открытым. Значение `Таблица.ПутьКДанным` из соседней EPF по-прежнему недоступно. Проба использовала известный реквизит штатной накладной.

Добавление в форме отменено штатным диалогом. Синтетическая запись удалена по точной ссылке с проверкой номера, даты и строк. Запрос подтвердил 0 накладных. Диагностический клиент и клиент обычной EPF остановлены. Менеджер на 17825 оставлен на обычной EPF в режиме `ask`.
