# 11.2 — caption, последовательность окон и активизации — 17.11.2026

Актуализация: [локальная проверка идентичности и фокуса](uilog-identity-focus.md) выполнена на сохранённом параметре без новой записи. Ниже сохранён результат этапа исправления импортёра.


Исправление проверено на **том же сохранённом uilog 8.5.1.1529**, без новой записи и без исполнения UI. Raw XML и его SHA не менялись. Импорт теперь возвращает **status=draft**, один шаг test_input/text и обязательную секцию ревью трёх исходных событий. Это полный черновик для разбора, **не доказанный эквивалент исполняемой записи**: конечный фокус ещё требует подтверждения.

## Точные правила

- ClientApplicationWindow принимает caption либо прежний title. При наличии обоих значения должны совпадать точно; конфликт блокирует импорт. Вложенная Form сохраняет собственный title. Заголовки не нормализуются и ` *` не отбрасывается из результата.
- ClientApplicationWindow/Form непосредственно внутри uilog — последовательные блоки записи. Их повторение сохраняет порядок и все действия, не трактуется как две одновременно существующие цели. Вложенные коллизии целей по прежнему правилу остаются поводом блокировки; единственность живого UI по записи не объявляется.
- Непосредственное `FormField/activate → inputText` с точно одинаковыми контекстом окна/селектором поля связывается с одним составным test_input. Сам драйвер всегда активизирует поле перед вводом. Оба исходных события, пути и хеши сохраняются, а не удаляются из черновика.
- Следующий одиночный activate **другого поля** может стать только кандидатом завершающего finish_edit, если заголовок совпал либо получил суффикс ` *`. Это синтаксическая граница предложения, **не доказательство идентичности формы**. В секции ревью обязательны confirm_same_form_across_blocks и confirm_exact_finish_target. Равный текст/звёздочка не разрешают исполнение.
- Если следующая активизация открывает следующий inputText, она принадлежит следующему вводу; её не поглощает предыдущий шаг. Непарная активизация, другой заголовок, неразобранный узел или конфликт не пропускаются: полный импорт blocked/draft=null.

Причина ограничения финального фокуса подтверждена текущим драйвером: `ЦельЗавершенияВводаUI` выбирает первое доступное непосредственное поле/кнопку, а при отсутствии цели используется переход к следующему элементу. Поэтому импортёр не может гарантировать конкретное поле «Номер» при будущем выполнении. Подмена field.activate действием activate_window/click не добавлена; публичные действия, BSL и capabilities не расширялись.

## Совместимое расширение черновика v1

Добавлено необязательное поле `recording_review`: SHA исходного XML и до 100 compositions. Каждая содержит step_id, правило, 2–3 события с типом, исходным путём/хешем, точными window/element и обязательства ревью. Значение inputText остаётся только в parameter_values; события ссылаются на его шаг. Бюджет всего черновика 256 KiB сохраняется.

Обе копии JSON Schema синхронизированы. При наличии recording_review **state обязан быть draft**. Preflight дополнительно возвращает recording_requires_review; простая смена state на reviewed отклоняется схемой. Старые сценарии без этого поля сохраняют прежний контракт. Автоматического «очистить обязательства/пометить reviewed» нет.

Завершение ревью — явное авторство исполняемого сценария после подтверждения соответствия всех событий доступным командам/предусловиям. Удаление recording_review само по себе не является доказательством; исходный отчёт остаётся обязательным материалом ревью. Если точный финальный фокус невозможно выразить/подтвердить существующим вводом, нужен согласованный контракт действия/завершения, а не выбрасывание события. Новый runtime-контекст и полномочия всё равно проверяются общим preflight.

## Результаты

- [Новый отчёт импорта](evidence/uilog-native/import-fixed.json): draft, один шаг, три события, одно значение параметра, dispatch_count=0 и execution_ready=false.
- [Отчёт ревью](evidence/uilog-native/review-fixed.json): source_unchanged, сохранены все события; идентичность формы и точный конечный фокус остаются обязательствами, прежние снимки не выдаются за свежую проверку.
- [Preflight](evidence/uilog-native/preflight-fixed.json): blocked, draft_requires_review/recording_requires_review/context_unavailable. Не готовый к запуску план.
- **8 новых тестов**: сохранённый XML/schema/события/параметры, конфликт caption/title, повтор блоков без дедупликации, непарные activate, неизвестный узел между событиями, другое окно, обход через reviewed и совпадение схем.
- **15 регрессий импортёра** и **12 runner/preflight** прошли. Повтор обоснован изменением импортёра и общего формата/preflight; остальные принятые наборы не запускались. В первом запуске новых тестов было неверное имя Python-функции preflight в тесте; оно исправлено, затем 8/8 прошли. Старые 15/15 из того запуска не перезапускались.

Всего 35 различных тестов. Нового выполнения на 8.5, сборки EPF или записи uilog не было; использован подлинный сохранённый файл предыдущего этапа. Рабочая установка не обновлялась, наблюдатель не подключён, анонимизация отложена. 11.2 и другие незавершённые пункты открыты, 13/42 сохранены.
