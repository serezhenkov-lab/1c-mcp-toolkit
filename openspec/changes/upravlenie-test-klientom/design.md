## Действующий первый рубеж — управление интерфейсом управляемого приложения через встроенный HTTP на 8.5

Приоритет имеет [контракт MVP](tasks.md#http-mvp). Единственный основной маршрут: агент → встроенный HTTP/MCP-сервер EPF → клиентский менеджер → штатный TestManager API → тест-клиент 8.5.1.1529. Отдельный Python proxy не требуется: в существующем harness start_proxy() для embedded возвращает None, вызовы /api/test_* адресуются самой обработке. Продуктовый Python runner является отдельным потребителем HTTP и остаётся необязательным расширением, а не серверной зависимостью MVP.

Не создаём новое ядро и не переносим runner в BSL ради MVP. Общий lifecycle встроенного сервера, идентификаторы операций, разрешения, точная адресация и отказ от повтора неизвестной мутации сохраняются. Эксплуатация должна работать на штатной EPF с сохранённым профилем, без execute_code для настройки, тестовых проб и сигналов подтверждения. Пользователь отвечает штатной форме ask либо явно выбирает существующий разрешённый режим; обвязка из scenario-approval.md не входит в поставку.

Объект метаданных не ограничивает доступность команды. Формы документов/справочников, обработок/отчётов, регистров, констант, настроек и общие формы используют единый драйвер. Ограничения задаются по действию/виду элемента и сохраняются в coverage/ошибке. Меню, разделы и команды панелей обязательны; нативный API командного интерфейса отличается от кнопок формы и требует отдельной типизации/обхода в TASK-018/8.2 и вызова в новом TASK-014/4.5. Селектор/реестр целей реализуются один раз в 8.2 и переиспользуются в 4.5. Не применять общий набор свойств кнопки формы к командной кнопке без проверки API.

### Контракт команд v1 (зафиксирован 13.11.2026)

Нормативная целевая ветка — 8.5, проверенная сборка 8.5.1.1529, Windows/тонкий клиент. Другие сборки 8.5 требуют проверки возможностей перед объявлением готовности. В v1 на 8.3 новые UI-команды недоступны: status сообщает supported=false и unsupported_platform с фактической версией. Существующие инструменты Toolkit сохраняют поведение. Выборочное отключение функций на 8.3 с предупреждением — дальнейший вариант, не обещание совместимости v1.

#### Общая схема

Имя инструмента задаётся маршрутом MCP/HTTP, не дублируется в аргументах. Аргументы — JSON object. Неизвестные поля, значения action, неверные типы, лишние параметры другой операции и null вместо обязательного значения отклоняются как invalid_params до действия. Вложенные объекты также закрытые. Ниже `?` означает необязательное поле; остальные обязательны. Строки непустые, кроме вводимого text и ожидаемого пустого значения. Идентификаторы — непрозрачные строки 1–128 символов; клиент их не конструирует.

Общий вход: `request_id:string`, `session_id?:string`, `action:string` (кроме test_open/test_expect), `window?:Window`, `element?:Element`, `timeout_ms?:integer`, `params:object`. session_id обязателен кроме start, attach и status менеджера. Неприменимые window/element/session_id запрещены. params={} требуется и для операций без параметров. Канал/контекст чата берётся из существующего транспорта, не из доверенного пользовательского поля.

Ожидание по умолчанию: start/attach 120000 мс, expect 30000 мс, остальные UI 30000 мс, status 0. Допустимо 0–300000; 0 — одна проверка, без повторного опроса. Передача управления между проверками: 250 мс. По исчерпании бюджета новый вызов API не начинается. Непрерываемый вызов платформы может выйти за бюджет; ответ отражает фактическое время и неизвестный исход, не обещает отмену.

#### Адресация

Window — ровно один вариант: `{id:string}`, `{active:true}`, `{selector:{title?:string,form_name?:string,navigation_link?:string}}`; selector содержит хотя бы одно поле. Все сравнения точные, с учётом регистра, поля соединяются AND; wildcard/подстроки запрещены. Отсутствующее active — window_not_found, не выбор первого окна.

Element — `{id:string}` либо `{selector:{name?:string,type?:string,title?:string,path?:string[]}}`. Хотя бы одно поле обязательно; path — точные имена предков от формы, без целевого элемента. type: form/group/field/button/table/decoration. Поиск ограничен выбранным окном. Результат должен быть единственным даже при совпадении видимого и скрытого элемента; скрытая/недоступная цель даёт target_unavailable. ID привязан к session_id и поколению UI; после переподключения/закрытия/пересоздания — stale_target.

Row — `{id:string,snapshot_id:string}` либо `{where:[{column:string,equals:string}]}`. where непустой, колонки уникальны. column — имя элемента колонки, преобразование в ключ данных выполняет драйвер по наблюдаемому соответствию; угаданное совпадение запрещено. Поиск строки требует полного охвата кандидатов и ровно одного совпадения. Неполнота — incomplete_search, несколько — ambiguous_target. Позиционные индексы без снимка не принимаются. Изменение/сортировка таблицы инвалидирует snapshot_id и row ID.

Панель сообщений не закрывается. История сообщений вне текущего снимка не подразумевается.

На 8.5 без навигации проверяется текущая строка: `actual.scope=current_row`, `complete=false`, прочитанные values и found. Совпадение является свидетельством наличия только при независимо подтверждённой идентичности строки; несовпадение не доказывает отсутствия во всей таблице. Текущий адаптер такой идентичности не предоставляет: equals возвращает incomplete_search и verification=not_confirmed, actual.identity={status:unavailable,reason:stable_row_identity_unavailable}, values_verified=false. values остаются диагностикой, matched/found=false означают отсутствие подтверждения, а не доказанное отсутствие. cursor_changed/selection_changed описывают действия исполнителя, а не гарантируют отсутствие внешней смены строки. row/not_equals возвращает incomplete_search: полный обход без изменения курсора API не предоставляет. До и после чтения требуется независимое доказательство идентичности текущей строки; сравнение описаний из текстов ячеек таким доказательством не является. При смене строки либо невозможности подтвердить её идентичность возвращается incomplete_search. expect не меняет курсор или выделение. Для поиска по всем строкам с разрешённой навигацией предназначена отдельная операция test_table/find.

#### Лимиты и разрешения

depth 0–32, max_nodes 1–5000, limit 1–500; text до 65536 символов, link до 4096, path до 32 сегментов. Один ответ данных до 1 МиБ UTF-8; обрезание только по границам элементов, с truncated=true, reason и complete=false. Значение отдельного поля не обрезать до ложного сравнения: выдавать value_unavailable. cursor привязан к снимку, сеансу и параметрам чтения; устаревший — stale_target. Истечение снимка объявляется expires_at; снимок живёт не дольше сессии. Полноту нельзя заключать из количества возвращённых строк.

Чтение: status, inspect, expect, table/read/find с allow_navigation=false. Изменяющие: start/attach/detach/stop, open, input, все action, table/select/add/fill/delete, read/find с allow_navigation=true. Разрешение на навигацию не заменяет разрешения Toolkit. deny отклоняет до UI; ask использует общий запрос подтверждения; session_allow действует только в текущем разрешённом контексте. Никакая команда не повышает права пользователя. Диагностика после действия не должна инициировать мутации. Для составной команды разрешение проверяется до первого шага, при отказе дальнейшие шаги прекращаются, возвращаются completed_steps и failed_step.

#### Ответ и общий lifecycle

Обязательный envelope: contract_version="1", request_id, operation_id (null только до принятия), session_id (null до создания), status, execution, verification, observed_at (UTC ISO 8601 либо null), observed_state (object/null), data (object/null), messages (array), error (object/null). Отсутствующее наблюдение содержит data.observation_unavailable_reason. status: awaiting_approval/queued/running/succeeded/failed/unknown. Это внешние состояния UI-адаптера; внутренние статусы общего lifecycle отображаются в них без нового реестра.

execution: not_started/invoked/unknown. verification: confirmed/not_confirmed/not_requested. Для чистого чтения execution=not_started (нет мутации), успешное чтение — confirmed. Для действия invoked означает вызов, а не запись в базе. succeeded — команда завершена с требуемой проверкой; rejected/неподтверждённое действие даёт failed и not_confirmed. При невозможности установить исход — unknown. В running/queued/awaiting_approval verification=not_requested. Принятое действие с отказом диагностики не повторяется; execution остаётся invoked, если вызов достоверно завершён.

error={code,message,stage,details}; stage: validation/availability/permission/resolve/execute/verify/observe/lifecycle. Коды: invalid_params, unsupported_platform, unsupported_operation, manager_mode_required, client_context_unavailable, client_already_exists, session_not_ready, session_invalid, database_mismatch, client_not_owned, window_not_found, element_not_found, ambiguous_target, stale_target, target_unavailable, incomplete_search, value_unavailable, permission_denied, row_edit_pending, expectation_timeout, action_not_confirmed, connection_lost, request_conflict, result_expired, screenshot_target_unavailable, internal_error. details не содержит секретов; тексты проходят штатную анонимизацию, технические ID сохраняются.

Уточнение 15.11.2026 по устранению блокировки status квотой: `test_session/status` с `params.operation_id` является чтением существующей операции, без новой записи, очереди и собственного долговечного ключа. Для нового чтения внешний operation_id равен целевому, request_id отражает текущий запрос; data.operation — актуальное состояние цели. Повтор чтения обновляет состояние, а не возвращает кэш первого чтения. Ранее сохранённые status остаются доступны по старым ID и ключам; попытка занять ключ принятой команды другим содержимым по-прежнему даёт request_conflict. Свободный ключ чтения не резервируется и не используется как ключ идемпотентности будущих команд. status без operation_id сохраняет обычный lifecycle. Одинаковая семантика реализуется в embedded и proxy, без второго реестра. См. [реализацию и проверки](lifecycle-fast.md).

Ключ дедупликации — контекст канала/чата и request_id. После принятия сохраняется каноническое содержимое: имя инструмента, session_id, все параметры с раскрытыми defaults (включая timeout), селекторы и разрешение на навигацию. Порядок ключей JSON незначим, порядок массивов значим. Повтор того же содержания возвращает прежнюю операцию; изменение любого параметра — request_conflict. При потерянном ответе допустим только повтор прежнего ключа или status(operation_id), не новый ключ для автоматического повтора записи.

Status собственного запроса чтения не меняет запрошенную операцию: сохранённый envelope находится в data.operation, ID из чужого контекста не раскрывается (permission_denied). Общий lifecycle публикует retention/expires_at; UI-адаптер наследует сроки и квоты, а не задаёт отдельный TTL. После удаления результата прежний ключ остаётся запрещённым: result_expired. Потеря реестра после рестарта не разрешает исполнение прежних ключей. Принятая очередь не отменяется из-за тайм-аута HTTP/file; status доступен независимо от занятого клиента. Неготовый общий lifecycle — блокер интеграции.

### Сеанс и восстановление

Служебная форма хранит session_id, состояние, идентичность базы, дескриптор подключения, признак/доказательство владения и текущую операцию. Новый start не создаёт процесс, если судьба прежнего неизвестна. attach к отключённому собственному клиенту сохраняет владение только при проверке доказательства; attach к чужому остаётся без права stop.

Доказательство владения связывает факт запуска Toolkit с идентичностью процесса и базы; один повторно использованный PID недостаточен. Конкретный механизм проверяется прототипом. При невозможности восстановления после restart клиент можно переподключить для управления, но нельзя завершать как собственный. restart сохраняет /TESTMANAGER и настройки подключения, но сбрасывает session_allow; старая сессия и UI-ID недействительны.

### UI и ожидания

Внутри сессии ID ссылаются на конкретные окна/элементы, а не только подписи. Перед действием проверяется актуальность и единственность цели. Для строк используется селектор по колонкам либо позиция с идентификатором снимка; после сортировки/изменения таблицы позиция устаревает.

Исполнитель последовательно применяет шаг, завершает редактирование и считывает наблюдаемый результат. Составные действия формы выбора и заполнения строки имеют список выполненных шагов. Ошибка не вызывает автоматического отката или повторного заполнения. Не переносить из Answer42 цепочку изменения через другой метод после неподтверждённого ввода, автоматическую отмену строки и закрытие неудавшейся формы выбора. При незавершённом редактировании вернуть row_edit_pending; при сбое чтения после действия сохранить execution=invoked/unknown и не нажимать повторно.

Для поиска единственного значения недостаточно единственного совпадения в усечённом наборе. В пределах заявленного scope требуется подтверждённая полнота, иначе choice_search_incomplete с предложением сузить отбор. Соседние строки с одинаковыми значениями не являются одним объектом и не доказывают конец обхода.

Чтение таблицы через API может выделять строки/перемещать курсор и вызывать прикладные обработчики. Предлагается allow_navigation=false по умолчанию: если без навигации данные недоступны, вернуть диагностическое ограничение; явное allow_navigation=true разрешает обход. В этом режиме возвращать cursor_repositioned, cursor_restored, row_activation_possible и полноту. Не восстанавливать курсор после неопределённого исхода обмена. Классификация разрешений учитывает этот режим как потенциально изменяющий состояние UI.

При модальном окне возвращаются его ID, заголовок и доступные действия. Следующая явно адресованная команда может обработать его. test_expect только читает состояние. В ожидании применяется поддержанный платформой обработчик/продолжение, не цикл без пауз и не серверная транзакция.

Длительная операция после приёма освобождает запрос транспорта и публикует прогресс/итог через общий lifecycle. Чтение status не ставится позади долгого UI-действия как новая UI-команда. Для файлового маршрута приём команды и ответ о принятии должны завершать транспортный обмен, сохраняя саму операцию активной. Это адаптация существующего протокола, не новый транспорт.

### Разрешения, данные и снимки

Решение пользователя 13.11.2026 по идентичности строк: [прототип нативного наблюдателя](row-identity-851.md) и [архитектурное предложение](client-row-adapter-proposal.md) сохраняются **без внедрения**. Предлагаемый компонент внутри тестируемого клиента не входит в текущую реализацию Toolkit; его подключение отложено до отдельного поручения. Тексты ячеек по-прежнему не являются доказательством идентичности; 4.1/5.1/5.2 остаются открытыми. Пункт 1.4 и рабочая установка не затрагиваются.

Для проверки опасных операций классифицировать действия явно: inspect/expect/status и чтение таблицы — наблюдение; ввод, кнопки, открытие ссылок, переключение/закрытие форм и изменение таблиц — потенциальные побочные эффекты. start/attach/detach/stop также проходят установленную политику доступности/разрешений. Нельзя полагаться только на поиск опасных слов BSL. Проверка выполняется перед фактическим действием, в том числе после ожидания в очереди.

Локальная реализация 4.3 подключает test_open/test_input/test_action к существующим режимам основной формы Toolkit. deny отклоняет до мутации; ask открывает штатную форму подтверждения и сохраняет awaiting_approval/not_started/not_requested; session_allow выполняет без отдельного вопроса. Текущий шаг очереди хранит только контекст решения и окно, новый реестр операций не создаётся. Разовое согласие связано со снимком инструмента и всех аргументов, поколением разрешений и уникальным токеном текущего шага. При истечении срока, смене сеанса, параметров или поколения запоздалое решение не выполняет команду и не включает session_allow.

Проверка выполняется после очереди и непосредственно перед каждым изменяющим вызовом. Первое изменение погашает разовое разрешение; остальные шаги той же составной команды проверяют тот же снимок и поколение, не запрашивая новое согласие. Отказ до первого изменения даёт permission_denied, stage=permission, execution=not_started. Если часть команды уже вызвана, отказ не стирает execution и completed_steps. Отмена окна равнозначна отказу. Тайм-аут включает ожидание подтверждения; закрытие просроченного окна не является отменой уже вызванного действия.

Внутренние inspect/expect не требуют согласия на изменение. Общая доступность инструментов, транспорты, анонимизация, разрешения команд жизненного цикла и штатный restart остаются TASK-016/2.3. Сеансовый режим использует существующее поколение и сброс основной формы, не сохраняется как session_allow. Результат кнопки записи по-прежнему подтверждает только вызов и наблюдение; сообщения обязательности и запрос к базе проверяют результат записи отдельно.
