# TASK-012 — реализация и проверка 13.11.2026

## Результат

По отдельному поручению пользователя реализован локальный драйвер управления одним
тест-клиентом. Закрыты 2.1–2.2. Пункт 2.3 оставлен открытым: локальная часть
реализована, но штатный сетевой restart и старые UI-ID ещё требуют интеграционной проверки.

Изменены корневой XML EPF и основная форма; добавлена служебная
`ФормаМенеджераТестирования`. Proxy, встроенная регистрация tools и рабочая установленная
EPF не обновлялись. Драйвер написан самостоятельно: небезопасные launch/stop доноров
не переносились. Адаптация UI-функций Answer42 относится к последующим TASK.

Драйвер проверяет платформу/режим/базу, запускает текущий `1cv8c.exe` с TESTCLIENT,
проверяет WMI PID + CreationDate + токен своего запуска и владельца TCP listener.
API-ready подтверждается подключением и чтением окон. Ожидание продолжается
обработчиком, status читает локальный снимок; нового цикла запуска по тайм-ауту нет.
Stop один раз закрывает основное окно через API и наблюдает завершение процесса,
без kill и без ответа на модальный вопрос. Windows/localhost — явная граница v1.

Receipt записывается до запуска. Повреждённый или неопределённый receipt блокирует
второй start; после restart он не даёт права stop. Старый session_id не восстанавливается.
Текущая незавершённая операция при завершении менеджера становится unknown;
долговечный реестр операций здесь не создаётся. Его подключение остаётся TASK-016.

## Стенд и воспроизведение

  `.local/test-client-preflight/20261112/controlled85`, пользователь ApiProbe.
- Настройки защиты пользователя взяты из уже созданного стенда и не менялись.
- Финальная одноразовая копия: `.local/task012/run05/Toolkit-test.epf`.
- Исходники/инструкция: [tests/test_client](../../../tests/test_client/README.md).
- Использованы настоящие формы Toolkit; тестовые callbacks и fault injection

## Выполнение

Финальные отчёты: [основной прогон](evidence/task012-runtime.json),
[новый процесс менеджера](evidence/task012-recover.json),
[обычный режим](evidence/task012-normal.json). Все 32 утверждения успешны, без ручных действий.

| Проверка | Наблюдение |
| --- | --- |
| Обычный сеанс | manager_mode_required, процесс не запускается; restart не получает TESTMANAGER |
| Профиль другой базы | database_mismatch до подключения |
| Запуск | starting/running с ID, затем ready/confirmed после API |
| Второй start, в том числе после detach | client_already_exists, первого клиента не заменяет |
| Detach/attach | Процесс сохраняется; новый session_id; прежний даёт session_invalid |
| Порт без владения | Новый start запрещён; attach даёт owned=false, stop — client_not_owned |
| Штатный stop | Подтверждён выход собственного процесса |
| Модальный вопрос | stop не подтверждён; вопрос «Да/Нет» сохранён; ответ «Нет» задаёт отдельный тестовый шаг |
| Нулевой тайм-аут | Запуск не считается ready, процесс известен; второй start запрещён |
| Потеря процесса | disconnected/connection_lost без выдачи готового UI |
| Прерывание запуска | Локальная операция unknown; автоматического повторного запуска нет |
| Новый процесс менеджера | Receipt восстановлен; старый session_id отклонён; attach явный, owned=false; stop запрещён |
| Разрешения | session_allow прежнего процесса не восстановлен |

Смена менеджера проверяется новым процессом 1С на том же receipt. Отдельно исполнен
тот же helper добавления TESTMANAGER, который подключён к существующей процедуре
`ВыполнитьПерезапускСессии`. Это **не** сквозной вызов штатного restart через MCP:
сетевая доставка, handoff ответа и общий operation_id этим прогоном не проверены.

При раннем прогоне обнаружена неверная эпоха даты — исправлена, финальный observed_at
соответствует UTC. В тестовом PowerShell cleanup исправлен обход WMI: остаточный процесс
раннего прогона отдельно завершён после сверки PID, CreationDate и токена. Финальный
runner использует CIM и ту же проверку, не завершает процессы по одному порту/имени.

## Статика и сборка

- Платформенная проверка ThinClient/Server/HandlersExistence и сборка финальной
  тестовой EPF успешны. Основная конфигурация стенда не изменялась.
- XML служебной формы: 23 проверки, ошибок нет.
- BSL LS: проверены оба изменённых модуля, пропущенных файлов нет. Итог — findings,
  не clean. В новом модуле нет Error; остаются предупреждения сложности функций,
  оформления публичного интерфейса и WQL, который анализатор трактует как язык запросов 1С.
  Основная форма содержит прежние диагностики; общий отчёт не объявляется успешной
  проверкой всех 32 тысяч строк без замечаний. Сводка — [static](evidence/task012-static.json).
  Два узких подавления пояснены в коде: ПолучитьФорму для невидимого служебного состояния
  и Windows COM после проверки ОС. Ошибки компиляции ими не подавляются.
- Python-регрессия: 24 теста, OK. Сначала импорт был невозможен из-за ahocorasick;
  pyahocorasick 2.3.0 установлен только в `.local/task012/python-deps`, без изменения
  глобального окружения и рабочей установки. Журнал — `.local/task012/python-tests.log`.

## Что не подтверждено

Полный 2.3 остаётся открытым: сетевой restart Toolkit и проверка старых UI-ID.
Не выполнены публичный контракт семи команд, дедупликация/retention общего lifecycle,
HTTP/file и server_host, клиент-серверная база, прикладной документ и бизнес-приёмка.
Предупреждение безопасности перед готовностью API в этом прогоне не воспроизводилось:
тестовый пользователь уже настроен; отдельно проверен тайм-аут без ложного ready.
8.3 новой реализацией не запускалась; ветка отклонения есть в коде, полная совместимость
8.3 не заявляется. Произвольный ручной формат /F при attach отклоняется, если база
не подтверждена поддержанным форматом профиля; профиль и внутренний интерфейс описаны в README тестов.
