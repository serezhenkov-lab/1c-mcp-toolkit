## API и проверенная граница

Справка установленной 8.5 через bsl-context подтверждает метод `ТестируемоеПриложение.ПолучитьНакопленныеПоказателиПроизводительности(ОчиститьНакопленные)`, тонкий/толстый клиент, результат Структура. Параметр очистки по умолчанию Ложь; наш probe всегда передаёт Ложь явно. Донорский сброс перед шагом не перенесён.

На файловой 8.5.1.1529 получены `Вызовы=25`, `Длительность=0.1203`, `Отправлено=12535`, `Принято=161424`. Немедленное второе чтение с Ложь вернуло те же значения: чтение не очистило накопление. Единицы длительности/объёма в полученном описании метода не заданы; они сохранены как platform_native_unit_unverified, без неподтверждённого преобразования в секунды или байты. Вызовы имеют unit=count. Время ожидания runner измеряется отдельно монотонными часами Python в секундах.

## Контракт

Доверенный reader без аргументов возвращает `{binding, values}`. В binding обязательны session_id, client_instance (экземпляр процесса, не один переиспользуемый PID), counter_epoch. Их достоверность обеспечивает сборщик, не пользовательский сценарий. Смена любой привязки, чужой сеанс, ошибка чтения, пропавшее/нечисловое значение или уменьшение накопленного счётчика дают явное unavailable с причиной, а не ноль. Незаметный сброс с последующим ростом без смены эпохи не выявляется: это ограничение общего счётчика, продуктовый источник эпохи ещё не реализован.

Runner после guard читает начальные показатели, отправляет команду и ожидает результат через существующий lifecycle, затем читает конечные. Артефакт связан с run_id, step_execution_id и operation_id, содержит исходные samples, источник, границы и дельты. При unknown метрики не доказывают завершение UI-действия. Отдельного журнала исполнения нет. Повтор доставки сохранённого результата не создаёт новый замер и не сбрасывает счётчики.

`wall_seconds` охватывает отправку/ожидание ответа без вызовов reader; разность платформенных счётчиков дополнительно включает границы чтения и возможную фоновую работу клиента. Поэтому attribution=shared_client_interval_not_exclusive, aggregation=do_not_sum. Вложенные/параллельные счётчики не суммируются и не выдаются за исключительную стоимость шага. `interval_union_seconds` объединяет перекрывающиеся интервалы только одного процесса/домена монотонных часов; caller обязан обеспечить эту границу. Это не время человека и не чистое серверное время.

Исключение диагностики не меняет статус/результат действия и не запускает повтор. Reader должен быть доверенным, с ограниченным временем выполнения: runner не прерывает произвольный зависший Python callback. В продуктовый транспорт reader пока не подключён. На стенде использован отдельный короткий вызов API менеджера без очистки; это обвязка, не клиентский наблюдатель.
