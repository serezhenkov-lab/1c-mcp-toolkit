# TASK-020 / 10.3 — доступная query-интеграция

16.11.2026. Реализована и проверена доступная часть 10.3 на отдельной файловой копии базы, платформа **8.5.1.1529**, маршрут **HTTP proxy**. Наблюдатель не подключался. Полная задача и UI-ветка остаются открытыми.

## Что подключено

`tests/test_client/query_verification.py` связывает независимый эталон, доверенный контекст чтения и структурированный ответ существующего execute_query с компаратором. JSON декодируется с Decimal; дубли ключей/нечисловые константы отклоняются. Бизнес-подтверждение допускается только при точном query_result, одной ожидаемой и одной фактической строке, наличии ссылки на документ в схеме. Сам компаратор сохраняет business_confirmed=false; отдельный результат обвязки имеет область `one_document_query_projection`.

Это интеграция в тестовый harness, без нового публичного API/шлюза и без изменений lifecycle. Обвязка сама не отправляет команды и не повторяет запросы. Доверенная привязка устанавливается запускающим стендом; не принимать эти утверждения от публичного клиента без проверки.

`run_query_verification.py` использует копию `.local/lost-response/http/db`, где документ ранее создан через UI. Эталон UUID/маркер закреплён из прежнего протокола **до** нового запроса; фактический результат не используется для автозаполнения эталона. Сопоставлены SHA исходной базы и копии до запуска, путь базы прочитан из запущенного менеджера, версия прочитана на сервере. Это новый итоговый запрос к копии прежнего бизнес-результата, **не новый сквозной прогон UI-записи**.

Запрос возвращает ссылку, маркер и пометку удаления по точному маркеру. Эталон требует одну строку, исторический UUID и `deleted=false`; лимит 10. Fingerprint вычисляется из фактически отправленных текста/типизированных параметров, база закреплена за изолированным маршрутом. Ни пользовательский SQL, ни его результаты не получают привилегированного пути выполнения.

## Найденные особенности и исправления

1. В proxy режим TOON по умолчанию возвращал data как строку (даже при fallback на JSON). Обратный разбор форматированного data не добавлен: отдельный тестовый proxy запускается с существующей настройкой `RESPONSE_FORMAT=json`.
2. Реальная схема колонок содержит `Null` вместе с конкретным типом. Нормализатор теперь отличает nullable-схему с одним конкретным типом от неоднозначного объединения нескольких типов. Ненулевые значения проверяются по конкретному типу; фактический null по-прежнему требует явной null_policy. Ограничения контракта не ослаблены.
3. В первой обвязке исправлен синтаксис служебного чтения версии. Песочница не позволяла прочитать ibases.v8i: полноценный запуск выполнен от основной учётной записи с прежними границами тестовой копии.
4. Два запуска остановились при подготовке из-за отсутствия места на C:. Удалены только собственные временные копии EPF/баз неуспешных попыток, протоколы сохранены. Финальный запуск читает уже существующий тестовый EPF без лишней копии. Рабочая установка не обновлялась.
