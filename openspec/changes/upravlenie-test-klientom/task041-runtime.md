# TASK-014/4.1 — ввод и проверка принятого значения

## Реализовано

Во внутренний последовательный клиентский исполнитель добавлен test_input с проверкой формы, однозначного поля, доступности, вида поля и параметров до мутации.

- text: ВвестиТекст; пустая строка — отдельный вызов Очистить.
- check: чтение исходного состояния, не более одного циклического УстановитьОтметку и readback boolean. Совпадающее исходное состояние не переключается. Неизвестное/третье состояние не преобразуется в false.
- select/list_value: точное сопоставление отображаемого текста со структурой списка, проверка всех кандидатов до выбора; два одинаковых текста не объединяются. Принятое значение сверяется с ПредставлениеДанных, которое может отличаться от ОтображаемыйТекст. Более 500 пунктов или неизвестный формат — choice_search_incomplete без выбора. Неоднозначность — ambiguous_target; список автоматически не закрывается.
- Завершение ввода: до мутации выбирается другой непосредственно подчинённый форме доступный элемент для перевода фокуса. При отсутствии такого элемента заранее выбирается ПерейтиКСледующемуЭлементу. Выполняется ровно один выбранный способ, затем проверяются уход фокуса и представление данных. Если поле остаётся активным, подтверждение не выдаётся.
- before отделён от actual. completed_steps фиксирует достоверно завершённые шаги; перед каждым изменяющим вызовом execution=unknown, после возврата — invoked. При исключении нет повторного ввода, альтернативного метода, отмены редактора или закрытия выбора. Ошибка readback не отменяет факт вызова.

Это внутренний клиентский вход. Разрешения и публичные маршруты остаются 4.3/TASK-016; рабочая установка не обновлена.

## Разрешённые зависимости и незавершённая часть

Пользователь отдельно разрешил необходимые части 5.1–5.2. Для табличной формы реализовано только безопасное чтение существующего выделения и диагностика кандидатов: scope=selected_rows, complete=false, без навигации. Имя колонки сопоставляется с наблюдаемым заголовком API, проверяется его однозначность. Одинаковые описания сохраняются отдельными кандидатами, identity_confirmed=false. Два совпадения дают ambiguous_target; один кандидат в неполной области — choice_search_incomplete. Строковые ID без выданного актуального снимка отвергаются как stale_target. Ввод в колонку таблицы отвергается до мутации без подтверждённой идентичности строки.

**4.1, 5.1 и 5.2 остаются открытыми.** Успешный выбор через табличную форму, устойчивый row_id и полный поиск не реализованы. Добавление/заполнение/удаление таблицы не подключены. Отказ от недоказанного выбора не считается выполнением этих требований.

Проверены альтернативы доказательства: ПолучитьТекущуюСтроку и ПолучитьВыделенныеСтроки возвращают описания из отображаемых текстов; ПерейтиКСледующейСтроке не возвращает признак окончания; ПерейтиКСтроке ищет по текстовым парам, включая маски. В runtime два повторных чтения одной неизменённой строки возвращают разные объекты соответствий. Поэтому ни равенство текстов, ни сравнение ссылок на эти соответствия не принято за независимую идентичность. Из этого не делается вывод о невозможности всех потенциальных решений; необходим отдельный подтверждённый способ адресации до завершения табличного пути.

Финальная копия `.local/task041/run5`; регрессия `.local/task041/regression`. Результаты: [ввод](evidence/task041-runtime.json), [регрессия UI](evidence/task041-regression.json), [статика](evidence/task041-static.json), [SHA-256](evidence/task041-sha256.json). Соответствие производственного исходника обеим тестовым копиям проверено после удаления тестовых вставок.

**Runtime: 31/31 проверок ввода и 79/79 регрессии UI.** Проверены текст/очистка, включение/выключение и отсутствие повторного переключения флажка, полный уникальный список, два одинаковых отображения, 501 пункт без выбора, исправление значения обработчиком формы, readback-сбой после вызванного ввода и unknown с сохранённым редактором без повтора/отмены. Для таблицы проверены два отдельных одинаковых кандидата, неполнота, отсутствие навигации и отсутствие устойчивого объектного соответствия для одной строки. Эти положительные проверки безопасных отказов не подтверждают успешный табличный выбор.

Платформенная проверка ThinClient/Server/HandlersExistence и сборка обеих EPF успешны. BSL LS: 411 диагностик, Error=0, статус findings; чистый анализ не заявляется. Подготовка копий Python выполнена; общая Python-регрессия отдельно не запускалась.

Промежуточные прогоны исправлены до финального: конфликт имени Окно со свойством формы; перевод фокуса в конце обхода; в тесте неизвестного исхода различены текст редактора и ещё не изменённые данные. В рабочем алгоритме альтернативные мутации после отказа не добавлялись.

Успешный табличный выбор, другие платформы, публичная интеграция и бизнес-приёмка не проверены. 1.4 открыт; Открыть() не исследовался и не изменялся.

Продолжение исследования: [нативные ID строк на 8.5.1.1529](row-identity-851.md). Для коллекции формы независимые ключи подтверждены внутри тестируемого клиента; маркер выделения опровергнут контрпримером. Универсальный клиентский адаптер и успешный выбор ещё не реализованы.
