# TASK-016 / 6.2 — схемы и отказы до принятия операции

14.11.2026. Выполнена доступная часть без клиентского адаптера. **6.2 остаётся открытым**: общий lifecycle не готов, полноценная интеграция не подменяется отказом. Требования TI-01/TI-02 и контракт v1 не упрощались.

## Реализация

- `onec_mcp_toolkit_proxy/test_client_contract.py`: схемы семи групп и всех действий из design.md. Закрытые объекты, типы и лимиты, варианты Window/Element/Row/Cell/Choice/Condition; отдельная проверка уникальности колонок в where/values. Схемы описывают вход, а не подтверждённые возможности платформы. Добавлена зависимость jsonschema в requirements.txt.
- `/api/test_session`, `/api/test_open`, `/api/test_inspect`, `/api/test_input`, `/api/test_action`, `/api/test_table`, `/api/test_expect`: новые REST-обработчики проверяют вход и отказывают до принятия/очереди. Некорректный вход — invalid_params, валидный — client_context_unavailable. Исходные значения не включаются в ошибку. Неподдержанный Content-Type — 415, повреждённый JSON — 400.
- `_execute_1c_command`: такой же отказ до ожидания consumer, в том числе для server_host и файлового режима. Это не разрешает proxy самостоятельно исполнять UI и не переносит в него политику разрешений.
- `ПроверитьДоступностьИнструментаMCP` в основной форме и модуле объекта: семь имён возвращают явный client_context_unavailable вместо unknown до любого dispatch. Прежняя защита клиентского диспетчера из 6.1 сохранена.

Отказ пока использует существующий транспортный формат success=false/error; это не envelope принятой операции v1. Operation ID не выделяется, запись операции не создаётся, наблюдение UI не выдумывается. REST status отвечает сразу отказом даже без consumer; это **не** доступность сохранённого статуса долгой операции.

Схемы пока не опубликованы в MCP tools/list и встроенном tools/list: общая регистрация, проверка входа в BSL и адаптер результата ещё не готовы. Вызов встроенного tools/call по известным именам получает явный отказ. Доступность REST-маршрута не означает готовность UI-команды.

Синхронная защита добавлена в две существующие копии проверки доступности, помеченные GENERATED. Генератор/шаблоны в репозитории не найдены; изменение ограничено одинаковым блоком отказа в обеих копиях. При появлении генератора необходимо перенести туда этот блок, иначе повторная генерация может его стереть.
