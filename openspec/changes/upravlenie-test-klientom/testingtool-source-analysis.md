## TT-01. Запись действий → дерево → исполнение

Конвертер, 23–90: читает XML `uilog`, формирует дерево, при необходимости добавляет подключение и отключение. Вложенные окна/формы/команды разбираются отдельными процедурами; неизвестный узел сохраняется с описанием и вызывает исключение. `мСцен_ConvertWindow` (202–255) выделяет тип, заголовок и IsMain, создаёт узел с UID/FUID. Это ID узла сценария, не идентичность живого UI-объекта.

**Полезно:** возможный будущий импорт пользовательской записи в черновик сценария Toolkit. Разделить преобразование записи, проверку получившихся команд и их исполнение. Неизвестные действия сохранять для диагностики, а не молча пропускать.

**Условия:** запись ещё не содержит строгих селекторов, проверок результата и доказательства идентичности строк. Импорт должен требовать пересмотра таких мест. Это отдельная будущая функция, не условие завершения текущих test_*.

## TT-02. Явные параметры действия и контекст клиента

В обработке действий параметры содержат тип, имя, заголовок, родителя, интервал и текущий порт. Текущее окно/объект хранятся в соответствиях по порту (например, 516 и 346). Поиск поддерживает варианты имён/заголовков через `|`. Параметры строк подставляются до вызова ПерейтиКСтроке (650–675).

**Полезно:** отделённое описание действия и возможность параметризации сценария. **Адаптация:** контекст Toolkit привязывать к session_id и поколению формы, не к одному порту; альтернативы селектора делать явными и проверять все совпадения до мутации.

## TT-03. Поиск не соответствует нашей однозначности

`мСценСкрипт_НайтиОбъект` (425–518) при множественных совпадениях выбирает первый объект либо первый доступный. Условие в строках 501–502 дважды проверяет ТекущаяДоступность; отдельной проверки видимости там нет. Вариантный поиск прекращается на первом успешном варианте. Нулевой интервал заменяется пятью секундами.

Это источник тестовых примеров, а не готовый resolver для Toolkit. Требуются ambiguous_target, отдельное значение «без ожидания» и явная неполнота поиска. Для строк используется описание значений; уникальность и устойчивый row_id не доказаны.

## TT-04. Подключение и очистка

`мСценСкрипт_GenerateClientConnection` (41–103): создание объекта через Выполнить, повтор Connect до срока, сохранение последней ошибки; при нулевом интервале ожидание 70 секунд. В цикле нет явной паузы/передачи управления. Наша модель status и асинхронного ожидания этим не заменяется.

Рабочее место: 2031–2112 собирает клиентов сценария и исключает повторные порты, 6832–6853 запускает через ЗапуститьСистему либо плагин с PID. 6779–6829 содержит массовое завершение тестовых приложений, включая ветку «закрыть всех» при пустом пуле; в другом маршруте используется PID плагина. Вызовы плагина прослежены до границы, их реализация в этом анализе не проверялась.

**Не переносить:** массовую очистку и отождествление порта с клиентом. **Полезно для проверок:** пустой реестр запусков не даёт права завершать чужие процессы.
