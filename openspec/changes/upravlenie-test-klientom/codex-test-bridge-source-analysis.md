## CTB-01. Прогресс и артефакты шага

BSL `CTB_ВыполнитьСценарий` 142–238 сохраняет событие до шага и после него: индекс, action, name, status, actual/error и длительность. При ошибке собирает окна и формы, добавляет состояние до навигации, затем прерывает сценарий. `CTB_СохранитьПрогресс` 424–442 отправляет состояние серверному модулю; ошибка сохранения подавляется.

Python: `write_atomic_json` 149–152 пишет временный файл и заменяет основной; `emit_progress` 929–940 хранит текущую стадию, время и историю событий. Финальная обработка 1863–1924 выносит тяжёлую диагностику в отдельный файл и создаёт summary с последним успешным шагом.

**Полезно:** короткий статус + ссылки на подробные артефакты; до/после навигации; последний завершённый шаг. В Toolkit следует привязать это к существующему operation_id и журналу, не вводя второй реестр.

**Ограничения:** запись прогресса до/после шага не является живым heartbeat внутри зависшего вызова. BSL durationMs вычислен через ТекущаяДата, то есть название поля не гарантирует миллисекундную точность. passed после возврата действия не доказывает бизнес-результат без отдельного readback. Автозакрытие форм после ошибки не переносить в диагностическую операцию.

## CTB-02. Нормализация селекторов

BSL `CTB_НайтиОбъект` 3433–3463 сначала вызывает НайтиОбъект. Только при отсутствии результата запускает нормализованный обход и отказывает при нескольких кандидатах. `CTB_НормализоватьUIТекст` 3494–3500 нормализует регистр, обычные/неразрывные и повторные пробелы.

**Полезно:** диагностические подсказки о похожих заголовках, особенно с неразрывными пробелами. **Не переносить буквально:** первичный НайтиОбъект не проверяет множество совпадений; fallback ограничен глубиной 8 и пропускает ветви при исключении, не возвращая признак неполноты (`CTB_СобратьКандидатыUI`, 3465–3492). Одно найденное совпадение здесь не всегда означает доказанную уникальность. В Toolkit нормализацию лучше сначала использовать в подсказках, сохраняя строгий исполнитель.

## CTB-03. Состояние и ожидания

BSL 2763–2776 собирает exists/name/title/visible/enabled/readOnly/dataRepresentation/editText. Проверка 3063–3085 не принимает неизвестное проверяемое свойство за ожидаемое значение. `CTB_ОжидатьЭлемент` 3096–3107 сообщает последнее состояние при таймауте.

**Полезно:** последнее наблюдение при таймауте. **Ограничение:** пауза 3109–3114 реализована поиском заведомо несуществующей формы с таймаутом 1 с; исключение подавляется. Это не гарантия неблокирующей работы или точного шага ожидания. Нельзя отождествлять ошибку поиска с отсутствием объекта.

## CTB-04. Снимок окна на отдельном desktop

`capture_window`, Python 13–102: EnumDesktopWindows, отбор видимых окон по PID, выбор наибольшего по площади, PrintWindow и сохранение BMP. Ресурсы GDI/desktop освобождаются в finally.

**Полезно:** направление решения TASK-016/6.4 для отдельного тест-клиента. **Нужно адаптировать:** проверить идентичность процесса/сеанса и HWND; наибольшее окно не обязательно активный модальный диалог. Проверить изображение на стенде, включая скрытый desktop, несколько окон и недоступность PrintWindow. Лицензионная неопределённость остаётся. Не считать это проверкой совместимости нашей компоненты снимков.

## CTB-05. Восстановление процесса и риск повторного исполнения

Python `wait_for_port` 836–847 разделяет раннее завершение процесса и отсутствие TCP-порта, использует monotonic deadline. Это хорошая предварительная диагностика; открытый TCP-порт не подтверждает готовность TestManager API или идентичность базы.

`wait_for_restarted_test_client` 890–907 на Windows находит PID слушателя порта и вызывает backend.adopt. `adopt` 733–740 открывает handle с правом завершения. В этих функциях нет проверки базы, времени создания и маркера запуска. Сам слушатель порта не должен становиться доказательством владения Toolkit.

`should_recover_stalled_windows_step` 1029–1066 ограничивает число попыток и учитывает таймаут шага. Маршрут 1717–1749 завершает менеджер и запускает ту же manager_command. Без отдельного доказательства checkpoint/idempotency это не гарантирует отсутствие повторного исполнения уже начатых действий. Для Toolkit потерянный ответ остаётся unknown до независимой проверки результата.

Очистка 1841–1861 завершает зарегистрированные worker процессы в finally. Полезна идея реестра созданных ресурсов, но корректность включения adopted процесса требует проверки.

## CTB-06. Таблицы

`CTB_ОсмотретьТаблицу` 2505–2569 активирует таблицу; при отсутствии выделения переходит к первой строке. Формирует карту заголовков и имён без отдельной проверки дублирующихся заголовков. `CTB_ПерейтиКСтрокеОбходом` 3026–3053 обходит до 5000 строк и возвращает первое совпадение; ошибка/конец/лимит сводятся к false.

Для нашего inspect это побочные изменения; для поиска — недостаточное различение not_found/incomplete_search и отсутствие доказанной уникальности. Стабильный row_id этим маршрутом не решён.

## Результат

Наиболее полезны формат артефактов, диагностические снимки до/после действия, monotonic deadlines и направление захвата по PID+desktop. Recovery, автоматическая очистка и табличный обход требуют существенной переработки. Код не переносился; все выводы о применимости пока кандидаты для общего решения.
