# TASK-021 — продуктовый сценарий появления и закрытия окна

17.11.2026. Следующий доступный пакет из единого остатка — test_open по e1cib-ссылке, close и оконные ожидания exists/closed. Это не метод Открыть() значения ячейки из пункта 1.4; к нему не возвращались.

## Реализация

Добавлены четыре ключа: test_open:open:scalar:none, test_action:close:scalar:none, test_expect:exists:window:none, test_expect:closed:window:none. Итого 19 capabilities на HTTP/file/embedded файловой 8.5.1.1529. Основания — task013-runtime.md и task042/task043-runtime.md плюс новая продуктовая приёмка ниже.

Для exists/closed **без element** введён отдельный вариант window, чтобы не выдавать оконную приёмку за поддержку отсутствия произвольного поля. Guard получает свежий test_inspect/windows, требует complete=true и массив окон, сопоставляет точный selector. Ноль или одно совпадение допускают только команду наблюдения: значение/ожидание подтверждает публичный исполнитель. Несколько совпадений либо неполное наблюдение блокируют отправку. Ошибка дерева не является доказательством отсутствия.

Для close/test_open исключение отсутствующего окна не применяется: сохраняется прежний guard дерева и общий lifecycle. Политика точных команд, свежий контекст, лимиты и запрет повтора неизвестного действия остаются. Скрытые/недоступные поля и закрытие с вопросом не обходятся новым guard.

## Новая приёмка

2. test_open с e1cib/list/Документ.T43_Required из Action Fixture.

4. Явный test_action/close списка.
5. closed=true для отсутствующего списка.

Проверка exists для поля (scalar) не разрешена оконным ключом. Другие платформы/клиент-серверный режим не проверены.
