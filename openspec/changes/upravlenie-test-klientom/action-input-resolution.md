# TASK-021 — unknown на Action Fixture: причина и итог приёмки

17.11.2026. Непринятый сценарий доведён до **succeeded на 8.5.1.1529**, файловая база, embedded HTTP, скрытый тест-клиент. Исправлена подготовка стенда; продуктовый код и итоговая EPF не менялись.

## Причина и доказательства

Общая обвязка run_native_document.py после запуска Action Fixture всегда открывала список Документ.T43_Required. Для нативного документного сценария это нужно, но сценарий внешней обработки затем обращался к полю на другой вкладке. Это отличие от прежнего успешного сценария на Fixture не было учтено.

Диагностическая копия EPF сохранила первичное исключение: **«Неподходящий тип элемента управления для вызванного действия»** в Поле.ВвестиТекст. completed_steps=[activate], before_confirmed=true. Последующие inspect/query работали, поле осталось пустым; реальная потеря соединения не подтверждена. Обобщение исключения в connection_lost/unknown сохранило запрет повтора, но скрыло точную причину. Стек записан только в диагностическую копию менеджера, без наблюдателя и без изменения политики выдачи ошибок в продукте.

| Условие на отдельной чистой копии | Наблюдение |
|---|---|
| Скрытый клиент, перед вводом открыт список документов | Воспроизведён unknown; получен первичный стек; значение пустое, документы неизменны |
| То же, явный activate_window | Действие выполнено, активность не подтвердилась (action_not_confirmed); диагностический ввод **не выполнялся** |
| Видимый клиент, список документов → подтверждённый activate_window Fixture | Ввод succeeded, activate/input_text/finish_edit; документы неизменны |
| Итоговая EPF, скрытый клиент, лишний список не открывается | Preflight ready; два шага input/readback succeeded, оба флага finish_focus=true; документы неизменны |

Таким образом, для этого стенда подтверждено влияние подготовки/состояния вкладки. Это не универсальный запрет ввода в скрытом клиенте и не доказательство, что любой отказ «неподходящий тип» имеет ту же причину. Финальный успешный скрытый запуск исключает необходимость постоянно показывать клиент.

## Исправление и завершённая приёмка

Добавлен режим --task021-input: обвязка оставляет исходную Action Fixture вместо открытия документного списка, а controller исполняет **только ранее непринятые два шага**. Continue_observation, файловый мост и другие уже принятые проверки не повторены. Самостоятельный diagnostic controller и режим видимого клиента сохранены для воспроизведения; видимость использовалась только в одном диагностическом запуске по ранее данному разрешению.

[Финальная приёмка](evidence/action-input-resolution/final-hidden/acceptance-summary.json): **3/3** — preflight, guarded input + readback (dispatch_count=2), неизменность девяти исходных документов. [Результат runner](evidence/action-input-resolution/final-hidden/runner-result.json). Исторический unknown не заменён новым результатом и автоматически не переисполнялся; каждый диагностический случай запускался на новой копии с новыми ID.

Все четыре набора собственных процессов завершены. В запуске hidden-activate проверка остановилась до ввода; итоговая query-сверка этого запуска не выполнена и не объявлена успешной. В трёх остальных диагностических/итоговом пакетах сверка документов прошла.

## Проверки и ограничения

Собрана отдельная диагностическая EPF с ThinClient/Server/HandlersExistence. Первая подготовка диагностического исходника остановилась на проверке числа обработчиков (их два), затем выбран первый UI-catch и собрана корректная диагностическая копия; ошибочно собранная до вставки копия не запускалась. Финальный runtime использовал прежнюю итоговую EPF без диагностического стека, её SHA совпадает с предыдущим этапом. Продуктовый BSL не менялся, новый BSL LS и прежние unit-наборы не запускались.

AST обвязки, SHA raw XML, cleanup, OpenSpec strict, git diff --check и 13/42 проверены. [Сводка](evidence/action-input-resolution/summary.json), [артефакты и хеши](evidence/action-input-resolution/sha256.json).

Рубеж TASK-021: доступная приёмка native/Fixture, файлового моста и embedded continue_observation завершена; этот unknown больше не является препятствием. Остаются продуктовый контекст, восстановление runner и неподготовленные/зависимые ветви общей приёмки. Пункты открыты, наблюдатель не подключён, анонимизация отложена, новой записи uilog нет, рабочая установка не обновлялась.
