## Реализация и ограничения

Новая запись реестра содержит собственные modes и evidence. Прежние строковые записи совместимы и наследуют прежний список режимов. Поставщик исключает ключ, если текущего режима нет в записи; digest всего реестра меняется вместе с маршрутами/доказательствами, и прежняя ревизия не считается той же capability_revision. Произвольный сценарий не может добавить себе supported.

Это 12 ключей для file-http и прежние 5 для file-file/file-embedded. Не добавлены таблицы, табличный выбор, группы-карточки, close, select_page, Открыть(), другие платформы/клиент-серверный режим. Для них требуется собственное подтверждение и соответствующая поддержка guard. Наличие положительного внутреннего вызова не объявлено полной продуктовой приёмкой.

Проверки свойств выполняются в текущих границах guard: однозначные существующие видимые/доступные цели; новый реестр не разрешает обход guard для скрытых/недоступных целей и не расширяет утверждённый scope. Нажатие кнопки подтверждает вызов и наблюдение; успех произвольной бизнес-операции требует отдельного ожидания/сверки.

## Новые сценарии

1. **window-observations:** активизация, title, visible, enabled, read_only — пять шагов через продуктовый CLI.
2. **checkbox-button:** check=true, click, readback счётчика=1, check=false — четыре шага через отдельный запуск того же CLI. Явная локальная политика разрешает только точные команды этих двух известных тестовых сценариев. Контекст получает продуктовый поставщик.

Четыре новых локальных теста: фильтр маршрутов; отсутствие неподтверждённых ключей; изменение ревизии при изменении маршрутов; выдача ограничения видимого окна для активации. Прежние подтверждённые наборы не запускались. BSL/EPF не менялись; повторной сборки нет.

При подготовке две попытки не дошли до сценариев: ошибка формата потока сначала в тест-клиенте, затем в менеджере. В harness активная TCP-проба заменена пассивным чтением слушателей netstat с проверкой PID своего клиента, старт клиента/менеджера разделён двухсекундной паузой; итоговая копия взята из последнего успешного стенда. Корневая причина ошибки не доказана и не объявляется устранённой одним успешным запуском. Все попытки и cleanup сохраняются отдельно.
