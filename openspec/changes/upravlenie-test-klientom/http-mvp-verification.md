## Исправления по результатам живого прогона

- Однократное повторное чтение снимка окон при кратком отказе наблюдения; UI-действия не повторяются. Изолированная проверка 3/3: стабильный, разовый и постоянный отказ.
- ErrorWindow учитывается как ошибка приложения даже при пустом штатном API текущей ошибки; положительно проверено на штатной консоли запросов.
- После очистки поля сменившаяся оболочка окна принимается только при совпадении нативной формы среди её детей. Реальное чужое окно продолжает блокировать ввод. Обе ветви проверены на 1744.
- Произвольный нативный отказ больше не называется доказанной потерей соединения; стадия вызова отделена от последующего наблюдения.
- Проверка открытия основной формы отчёта/обработки учитывает точную принадлежность метаданных при короткой прикладной ссылке. На 1802 оба открытия confirmed; activate_window переключил клиент с обработки на отчёт, формирование дало MVP_RESULT=14,00;VAR=A;DETAIL=1. Снимок report-client-1802.png: PID 43140, уникальное проверенное окно клиента, capture_complete=true.

Финальный клиент штатно остановлен: d37071fd-0483-45cb-b8c5-dc0385cc72e7,
process_state=Exited, owned=false. Режим возвращён в ask. Очищенная база выгружена
в DT (186377 байт), поставляемый Start-ToolkitMvp.ps1 запустил тот же кандидат
без harness; MCP прочитал метаданные и прежний результат stop после перезапуска.
Журнал healthy=true, инициализация завершена. Менеджер оставлен доступным,
тест-клиент остановлен. Сохранённая DT не восстанавливалась в ещё одну базу.

## Точные ограничения

- Полный охват таблиц/поиск одинаковых строк, click_group, произвольный MXL,
  наблюдатель, анонимизация test_*, остальные транспорты и полная матрица сред
  остаются открытыми задачами v1/TE. Этот протокол их не закрывает.
- Для test_* анонимизация должна быть выключена; иначе явный отказ.
- Составное StandardPeriod не принимает обычный текст; в штатную обработку
  добавлены два scalar-поля дат того же периода. Конец дня нормализуется
  платформой до 23:59:59; несовпадение readback не скрывается.
- Разворачивание группы «Отчёты» нативным Expand не подтвердилось; прямой
  command_button внутри группы выполняется. После unknown выполнялось только
  наблюдение, альтернативного нажатия для той же операции не было.
- Обычная форма исходной консоли запросов в этом тонком клиенте открывает
  ErrorWindow. Это проверка диагностики, не успешный запуск этой обработки.
- Инициализация журнала кратковременно даёт operation_store_unavailable
  без operation_id: команда не принята. На больших прежних журналах ожидание
  составляло несколько минут; удалением журнала готовность не имитировалась.
- Приёмка конкретного рабочего проекта пользователем этим стендом не доказана.
