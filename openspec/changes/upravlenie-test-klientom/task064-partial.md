# TASK-016 / 6.4 — явная цель снимка, неполная проверка захвата

14.11.2026. Добавлена доступная часть без клиентского адаптера. **6.4 открыт.** Захват окна тест-клиента не реализован. Повторная проверка с разрешённым видимым запуском подтвердила legacy/toolkit; первоначальные неуспешные пробы сохранены ниже как история. Требования TI-04 не сокращались.

## Компонента и ограничение

Исходник `native_components/ScreenCapture/src/component.cpp`: `GetNParams` задаёт семь параметров CaptureWindow — масштаб, сетка, координаты/размер области и выделение. В `CaptureMainWindow` PID берётся через GetCurrentProcessId; EnumMainProc и проверка foreground ограничены окнами этого процесса. PID/HWND другого клиента передать нельзя. Поэтому запуск имеющейся компоненты в менеджере не подтверждает снимок тест-клиента. Для реализации без клиентского адаптера потребуется отдельное расширение native API и проверка привязки PID/HWND к актуальному session_id; это здесь не реализовано.

На стенде успешно загружена компонента из макета ScreenCapture. SHA256 Template.bin: `DB53692087D378F4D1CBF80B230D9F8E2EAA81CB32C20E9040333C617389E793`. Исходники компоненты и бинарный макет не изменялись. Загрузка бинарника не считается проверкой всех свойств его исходного кода.

## Что изменено

- GetScreenshotParams, статическая Python-схема, MCP-сигнатура и обе BSL-схемы принимают target=toolkit/test_client и session_id. REST использует ту же Pydantic-модель.
- Отсутствующий target (и null) сохраняет прежнюю цель; явный toolkit использует прежнюю ветку захвата. MCP без target передаёт тот же набор параметров, что до изменения.
- test_client требует непустой строковый session_id до 128 символов и не принимает form_name/link/page_name менеджера. session_id без test_client отклоняется.
- Валидный test_client пока возвращает screenshot_target_unavailable **без изображения**, независимо от существования ID сеанса; актуальность ID здесь ещё не проверяется. Отказ в proxy происходит до ожидания consumer и до очереди. В BSL добавлен общий валидатор в обе копии runtime и ранние проверки в синхронном/диспетчерском захвате до обращения к компоненте и открытия формы.
- Отсутствие поддержки не заменяется активацией/снимком менеджера. Текстовая анонимизация изображения не заявляется.

Изменения затронули парные GENERATED-схемы/валидаторы формы и модуля объекта. Генератор в проекте ранее не найден; при его появлении изменения необходимо перенести в источник генерации. Новая чистая функция в форме имеет контекст НаКлиентеНаСервереБезКонтекста, поскольку используется также серверной проверкой аргументов.

## Повторная проверка и установленная причина

14.11.2026 по отдельному поручению пользователя проведено сравнение скрытого и явно разрешённого видимого запуска менеджера. В production-коде Toolkit/ScreenCapture изменений в этом расследовании нет; изменён тестовый harness.

- [Скрытый запуск](evidence/task064-hidden-windows.json): PID 7040, главное окно HWND 464182, parent=owner=0, размер 1438×753, visible=false, minimized=false. При этом [ПолучитьОкна()](evidence/task064-hidden-1c-windows.json) видит основное окно StubConfig и вспомогательное MCP Toolkit. Окно существует; оно отбрасывается `IsOurWindow` из component.cpp из-за `!IsWindowVisible(hwnd)`.
- Причина — `Start-Process -WindowStyle Hidden` в run_runtime.ps1. Штатное Активизировать() не сняло скрытость. Для данного случая гипотезу отсутствующего окна заменяет подтверждённая невидимость существующего окна.
- Добавлен явный `-VisibleManager`; стандартные фоновые проверки остаются Hidden. Для снимков флаг используется только после разрешения показать тестовый менеджер. Дополнительный `-WindowDiagnostics` запускает read-only инвентаризацию окон/модулей только собственного менеджера и его потомков; чужие окна не меняет. В тестовом BSL записывается список окон и даётся 5 секунд на диагностику перед захватом.
- [Видимый контроль](evidence/task064-visible-windows.json): PID 33400, HWND 464168, parent=owner=0, тот же размер 1438×753, visible=true. Свежая .local/task064/visible-control/Toolkit-test.epf, тот же стенд 8.5.1.1529 и неизменённый бинарник компоненты. Проверки платформы и сборка успешны.
- [55/55 runtime](evidence/task064-visible-runtime.json). Обе операции success=true, capture_complete=true, overlay_failures пуст. foreground_window.hwnd совпадает с наблюдаемым главным окном менеджера. Отказ test_client без подмены остаётся успешным.
- Получены [legacy.png](evidence/task064-legacy.png) и идентичный [toolkit.png](evidence/task064-toolkit.png). Визуально просмотрен legacy.png: на изображении заголовок «StubConfig — Менеджер тестирования» и форма MCP Toolkit. PNG 1438×753, по 40331 байту; SHA256 обоих `D401C90FDC8039F3E8FDF92C6B1E8927C30A9F0FD385D8320F3247365D249308`. Побайтовая идентичность проверена хешами; изображения не редактировались.
