## Стенд и подготовка

Отдельные копии файловой базы, платформа 8.5.1.1529, ApiProbe, тонкий клиент Windows, HTTP proxy из checkout, проверенная `Toolkit-production.epf` без новых BSL/нативных изменений. Менеджер/клиент и запросы привязаны к одной копии базы. Сырые паспорта содержат путь, base_id, session_id и SHA EPF. Наблюдатель отсутствует; рабочая установка не менялась.

Первый запуск выявил отсутствие кнопки «Создать». Платформенная ссылка на пустой документ открыла ErrorWindow: «Недостаточно прав для создания». Серверная проверка: Добавление=true, ИнтерактивноеДобавление=false. Из тестовой копии выгружено расширение Task043Fixture; в заимствованной роли ApiProbeAdmin для Document.T43_Required действительно были только Read/Insert/Update/View.

Только в этой остановленной тестовой копии добавлены InteractiveInsert и Edit. Прочие права/UUID сохранены; частично загружена одна роль расширения, обновление тестовой БД успешно. role-validate: 0 ошибок, 1 предупреждение пустого синонима, 9 проверок. Объект документа и его модули не менялись. Второй запуск использовал новую копию подготовленной базы. ## Новый результат

В свежем дереве списка обнаружены две команды с подписью «Создать»; обвязка отказалась выбирать первую. По наблюдённому имени `ФормаСоздать` выбран точный элемент командной панели; нативная форма создания открылась. Имена полей и кнопок получены из её inspect.

Ввод заданного номера вызвал штатный вопрос «Номер заполняется при записи автоматически. Продолжить редактирование?». Toolkit сообщил unknown после activate/input_text, connection_lost на наблюдении. Ввод повторно не отправлялся. Диалог прочитан, сделана явная попытка нажать «Нет»; ответ stale_target/not_started, последующий поиск MessageBox его уже не нашёл. Причинность исчезновения этим протоколом не доказана, неверная классификация результата — кандидат на отдельную локализацию. Автоответчик диалогов не добавлен. После исчезновения диалога inspect ещё показывал пустой номер; конечная запись сохранила ранее введённый номер. Это важное ограничение наблюдения незавершённого ввода, не доказательство отсутствия изменения.

После ввода даты прежние ID также дали stale_target до вызова записи; для последующих команд форма/элемент разрешались заново точными уникальными селекторами. Ошибки обвязки (повтор аргумента params; PowerShell Index вместо IndexOf) сохранены в ходе работы; одна лишняя попытка поиска уже отсутствующего MessageBox не исполнила действие. Успешные старые проверки не повторялись.

Нажатие штатной «Записать» с пустым обязательным полем вернуло succeeded для факта нажатия, а inspect/messages — `Поле "Обязательное поле" не заполнено`. Полный запрос документа до/после вернул одинаковые 9 записей. Это подтверждение бизнес-отказа, а не ожидание, что само нажатие должно иметь failed.

После заполнения ОбязательноеПоле уникальным маркером второе, отдельно предусмотренное сценарием нажатие «Записать» успешно. Запрос всех документов (лимит 1000, получено 10) дал ровно одну новую ссылку; сверены номер `T7590757ced`, дата `2026-11-16T12:00:00Z`, маркер `NATIVE:53f6e86b-66f5-4524-aa5d-e1053b71bbd4`, ПометкаУдаления=false. Запрос не отфильтровывал неправильный маркер: новая ссылка найдена разностью полного набора до/после. Служебная форма не использовалась для записи; программного СоздатьДокумент/Записать в проверке нет.
