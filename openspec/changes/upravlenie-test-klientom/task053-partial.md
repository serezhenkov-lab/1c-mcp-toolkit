# TASK-015/5.3 — частичный результат доступного добавления

14.11.2026. Реализована обработка частичного результата внутреннего `test_table/add` без values. Полный 5.3 остаётся открытым: заполнение нескольких ячеек и его частичный результат зависят от ещё не реализованной части 5.2 и независимой идентичности строки.

## Изменения

Ответ сохраняет прежний `completed_steps` и дополнительно сообщает `steps` для `add` и `observe_editing`. Состояния: `not_started`, `unknown`, `invoked` для добавления; `not_started`, `unknown`, `observed` для чтения. `invoked` означает возврат платформенного вызова, а не доказанную идентичность или успешную запись строки.

Перед добавлением прежнее значение `editing` очищается: при ошибке последующего чтения возвращается null, а не значение, полученное до мутации. После проверки разрешения, до вызова API инвалидируются старые UI-цели — неизвестный исход также делает старые цели недействительными. Исключение не направляет управление обратно к изменяющему вызову.

| Исход | execution / verification | completed_steps | steps | editing |
| --- | --- | --- | --- | --- |
| Исключение после вызова, до фиксации его возврата | unknown / not_confirmed | пусто | add=unknown, observe_editing=not_started | null |
| Добавление вернулось, чтение состояния не удалось | invoked / not_confirmed | add | add=invoked, observe_editing=unknown | null |
| Вызов и чтение вернулись | invoked / not_confirmed | add | add=invoked, observe_editing=observed | наблюдаемое значение |

`rollback_performed=false` описывает отсутствие компенсирующего действия исполнителя; оно не утверждает ничего об обработчиках прикладной формы. Автоматический повтор, отмена строки и имитация отката не выполняются. При уже открытом редакторе сохраняется прежний `row_edit_pending`, оба шага остаются `not_started`.

## Стенд и тесты

Тонкий клиент Windows 8.5.1.1529, ApiProbe, отдельная `.local/task043/db`, неизменённая InputFixture.epf. Менеджеры собраны из текущих исходников; инъекции добавлены только в одноразовые копии. Клиентский адаптер не загружался.

`prepare_runtime.py --table-failure unknown|readback|disconnect` создаёт три независимых прогона. `unknown` выбрасывает искусственное исключение непосредственно после настоящего `ДобавитьСтроку()` и до записи completed_steps; это имитация потери результата, не доказательство реального сетевого разрыва внутри вызова. `readback` внедряет `value_unavailable` перед чтением. `disconnect` действительно завершает собственный тест-клиент после проверки PID, времени создания и токена; последующее чтение получает ошибку связи. Реальный разрыв проверяется после возврата добавления, не в произвольный момент его исполнения.

В каждом сценарии проверяются статус и код ошибки, список завершённых шагов, состояния шагов, отсутствие устаревшего editing и заявления об откате, один фактический вызов и смена поколения UI-целей. В двух сценариях с живым клиентом независимо прочитан сохранённый режим редактирования. В сценарии disconnect проверяется подтверждение завершения принадлежащего тесту процесса. Отсутствие выполненного шага при unknown не означает, что строка не добавилась.
