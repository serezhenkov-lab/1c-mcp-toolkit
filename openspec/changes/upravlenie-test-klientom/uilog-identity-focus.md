# 11.2 — идентичность формы и конечный фокус, 17.11.2026

На отдельной файловой базе **8.5.1.1529, HTTP proxy** выполнен один публичный test_input с параметром из сохранённого uilog. Новая запись не велась. Наблюдатель не подключался; диагностический метод добавлен только в отдельную тестовую EPF менеджера, не в продуктовый BSL.

## Подтверждено

- До ввода сохранены нативные ссылки на форму, «ОбязательноеПоле» и выбранную существующим драйвером цель finish_edit — «Номер».
- После activate → input_text → finish_edit сохранённое поле равно вновь найденному и читает введённое значение. Текущий элемент и сохранённой, и вновь найденной формы равен **той же нативной ссылке «Номер»**, выбранной до ввода. Это проверка ссылки, а не равенства подписей.
- Форма закрыта без сохранения, отсутствие окна проверено, затем создана новая форма того же типа. Обе старые ссылки отклоняют чтение с «Объект не может быть найден»: они не переключились на новый экземпляр.
- Таким образом, непрерывность экземпляра и конечный фокус подтверждены для воспроизведённой композиции этой формы. Исходные девять документов не изменились; три собственных процесса завершены.

## Особенность API и границы доказательства

Сохранённый объект формы возвращает прежний заголовок, а вновь найденный — заголовок со звёздочкой. Равенство объектов формы после ввода false, хотя сохранённые методы/поле продолжают обращаться к живой форме. Поэтому заголовок и равенство оболочек формы не используются как независимый идентификатор. Нативный UUID формы не получен.

Первоначальный критерий пробы ошибочно ожидал обновления заголовка сохранённого объекта: итоговый assert завершился отказом. Исходный [протокол](evidence/uilog-identity/identity-focus-proof.json) сохранён без изменения. Проверка заменена на наблюдаемые свежий заголовок и идентичность поля; **11 критериев** сверены по уже сохранённым ответам, без повторного UI-запуска: [ревью](evidence/uilog-identity/review.json). Ранний технический запуск до ввода остановился из-за имени локальной переменной Окно; оно исправлено в тестовой пробе, EPF пересобрана с проверкой конфигурации.

Это не ретроспективное доказательство идентичности исходных окон XML: запись не содержит независимого ID. Подтверждена эквивалентность трёх событий одному составному вводу на проверенном экземпляре и расположении полей. Для другой формы/раскладки нельзя обещать тот же finish_edit: драйвер выбирает первое доступное поле/кнопку.

## Решение ревью и остаток

Обязательства live target/input activation, same form и exact finish target имеют локальные runtime-доказательства. Исходный draft и recording_review сохранены; автоматического reviewed/ready нет. Для переносимого исполняемого сценария остаётся закрепить проверяемое предусловие конкретной цели завершения либо согласованный контракт её явного выбора, а также получить свежий runtime-контекст полного preflight. Равный заголовок или удаление recording_review не заменяют эти условия.
