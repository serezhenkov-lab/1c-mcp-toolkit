# Запуск и восстановление — актуальный срез 17.11.2026

Инструкция относится к отдельному Windows-стенду с файловой базой 8.5.1.1529. В рамках актуализации 7.4 команды ниже **не запускались**. [Историческая инструкция 14.11](task074-runbook-20261114.md) сохранена; её утверждения об отсутствии публичного lifecycle/снимка клиента устарели.

## Проверенный нативный сценарий

Полные предпосылки, последовательность и ограничения — [нативный сценарий и очистка](native-scenario-cleanup.md). Нужны остановленная подготовленная копия с T43_Required/ApiProbe и InteractiveInsert/Edit, явно выбранная проверенная EPF, свободные порты и разрешённый запуск отдельного тестового клиента. Чужие процессы для освобождения порта не завершать.

Из корня checkout, последовательно для маршрутов http/file/embedded:

```powershell
& C:/1C/tools/ai/mcp/1c-mcp-toolkit/.venv/Scripts/python.exe -B tests/test_client/run_native_document.py http --batch --source-db C:/1C/dev/1c-mcp-toolkit/.local/native-document-20261116T121346/http/db --epf C:/1C/dev/1c-mcp-toolkit/.local/file-recovery-20261117/Toolkit-production.epf
```

Launcher создаёт новую копию, ждёт готовности общего lifecycle, подключает клиента и запускает controller. Старые каталоги доказательств не переиспользуются. Маршруты используют общий клиентский порт 16589, поэтому одновременно их не запускать. Проверенный результат каждого маршрута — 16/16, 9→10→9; команда не является универсальной установкой с нуля и требует сохранённых стендовых артефактов.

Очистка адресная: одна новая ссылка + точный маркер + проверка базы, транзакция и восстановление серверного привилегированного режима. Удаление не является откатом UI, журналов или нумерации. При ошибке/unknown нет автоматической повторной мутации или массовой очистки; сначала сверить сохранённый baseline, operation_id и фактические данные.

## Восстановление без повтора

- Потерян ответ: читать существующую операцию через test_session/status с operation_id; не заменять request_id новым для повторной записи. TTL/result_expired не дают разрешения повторить действие.
- Unknown после записи: сверить полный набор ссылок/значений той же базы и UI. Положительный запрос не переводит журнал в succeeded автоматически и не означает возможность повторить нажатие.
- [File recovery нового протокола](../archive/2026-11-19-rezhimy-podtverzhdeniya-i-izolyatsiya-chatov/file-recovery.md): HTTP доступен при blocked/executor_busy, новый сеанс публикуется после освобождения executor.lock. Не удалять current/running для обхода блокировки. Legacy/unclaimed без маркера и запись без подтверждённого журнала остаются blocked; готовой универсальной процедуры для них нет.
- [Управляющий restart](file-restart.md) не является повтором исходной команды. Неизвестный исход restart не разрешает вторую доставку или запуск второго клиента.
- Завершать только собственные процессы по сохранённому владению. Сохранить cleanup и доказательства; не очищать рабочую установку или исторические тестовые базы.

## Что не подтверждает эта инструкция

Нет приёмки клиент-серверного/RDP/server_host/Linux режима, полной матрицы отказов, таблиц или анонимизации. Наблюдатель не внедрён. Предупреждение безопасности внешней обработки не обходится автоматически. Ошибка формата потока первой копии нативного стенда остаётся отдельной неустановленной причиной, а не исправленным дефектом Toolkit. Проверенные маршруты/бинарники и ограничения сверяются по [матрице](task074-scenario-matrix.md), [протоколу](task074-acceptance.md) и SHA в первичных отчётах.
