# TASK-021 — наличие и состояние полей, строковый ввод и очистка

17.11.2026. Доступный пакет выполнен на отдельных файловых базах 8.5.1.1529, Windows thin client. Рабочая установка, Toolkit BSL и Toolkit EPF не изменялись. Наблюдатель не подключён, анонимизация отложена.

## Продуктовое изменение

- Добавлены `test_expect:exists:scalar:none` и `test_input:text:scalar:none`: реестр содержит 22 ключа на HTTP/file/embedded.
- Наличие поля проверяется по полному свежему дереву существующего окна и явному `selector.type=field`. Ноль совпадений разрешает наблюдение отсутствия; несколько совпадений или неполное дерево блокируют шаг. Это не доказательство отсутствия в command_interface/command_bars/table_additions.
- Guards наблюдения `visible/enabled/read_only` допускают скрытое/недоступное поле. Значение свойства должно быть известным Boolean; unavailable/null не становятся false. Нативная проверка условия выполняется после guard повторно.
- Ввод по-прежнему требует видимой доступной цели. Известное read_only=true теперь блокируется ещё guard; нативный исполнитель повторно проверяет вид поля и только просмотр непосредственно перед изменением. Остальные неизвестные/неподходящие виды не разрешаются по аналогии.
- Строковый ввод без finish_focus использует существующий нативный выбор цели завершения, проверку окончания и readback. Пустая строка вызывает Очистить(); отдельно подтверждена очистка с явным finish_focus. Импортированный шаг по-прежнему сохраняет обязательный записанный finish_focus.
- `editing` не зарегистрирован: на реальном поле inspect вернул null, unavailable_reasons.editing=property_read_failed. Guard не разрешил проверку false. Исправление/проверка этого API остаётся открытым остатком.
