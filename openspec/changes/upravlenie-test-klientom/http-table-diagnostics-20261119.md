## TASK-015

- 5.1. Чтение без разрешения на навигацию возвращает `scope=selected_rows`, `complete=false` и не вызывает выделение. Чтение второй страницы сохранённого снимка также обходится без навигации. Строки с равными прикладными значениями (количество 2, цена 3) имеют отдельные позиции. Служебный номер `N` различается, поэтому это не доказательство независимой идентичности.
- Выбор позиции с актуальным полным снимком проверен наблюдаемым изменением отображения текущей строки. Штатная сортировка поменяла порядок количества с `[2, 2, 11]` на `[2, 11, 2]`. Попытка выбрать прежнюю позицию остановилась с `stale_target` после разрешённого выделения, до выбора строки. При навигации `cursor_change_verified=false`: ответ отдельно сообщает изменение отображаемых значений и состояние восстановления `unverified`. Нативная идентичность курсора остаётся открытой.
- 5.2. Добавление и заполнение прошли с завершённым редактированием и чтением обратно. Удаление единственной совпавшей строки проверено отсутствием цели и изменением числа строк. Две строки с одинаковым количеством дали `ambiguous_target` до удаления. Заполнение по ID позиции отклоняется до вызова. Для изменения по точному `where` сохранён контракт HTTP-MVP.
- Штатная команда «Добавить» оставила активный редактор. Следующее навигационное чтение вернуло `row_edit_pending`, `execution=not_started` и наблюдаемые поля строки. Последующая диагностика независимо прочитала `editing=true`, текущую колонку и открытый список ввода. Автоматического завершения или отмены не было.
- 5.3. После ввода количества 11 и текста `abc` в числовую цену количество прочитано как 11, цена пустая. Ответ вернул `failed`, `action_not_confirmed`, `cell_steps=[confirmed, invoked]`, последний завершённый шаг `finish` и `rollback_performed=false`. Повтор успешного заполнения с исходным `request_id` вернул тот же `operation_id`.
- В одноразовой сборке пауза после первой ячейки позволила завершить доказанно собственный тест-клиент посередине операции. Сохранён `unknown` на стадии `invoke`, `completed_steps=[select_all, add, cell]`, `cell_steps=[invoked, unknown]` и `rollback_performed=false`. Повтор исходного запроса вернул тот же `operation_id` `1186b15d-9e27-4e49-8bba-144f0319562f` и прежний исход. Ошибка в API имеет общий код `action_not_confirmed`. Факт обрыва установлен отдельно по завершению процесса.

## TASK-018

- 8.2. Для отсутствующего точного селектора возвращён ограниченный список подсказок с `exact_matches=0`; действие не выполнялось. Неполное дерево с малым лимитом сохранило признак неполноты. В коде при недоступном свойстве резолвер сохраняет причину и кандидатов, не подбирая другой селектор. Эту ветвь отдельно на стенде не воспроизвели. Матрица предков и типов остаётся открытой.
- 8.3. Неоднозначность адресации попала в `errors.command`, несовпадение цены после ввода — в `errors.observation`. Наблюдаемое состояние приложения передано отдельно. Снимки `before/after`, последний шаг и ссылки артефактов относятся к исходному `operation_id`. Чужой канал получил `permission_denied` без содержимого операции. Анонимизацию и исчерпание диагностического бюджета в этом прогоне отдельно не проверяли.
