# TASK-021 — остановка после вызванной, но неподтверждённой мутации

17.11.2026. Следующий пакет выбран из единого остатка: реальный отказ ввода и восстановление runner после него. Проверена файловая база на 8.5.1.1529 через file, HTTP и embedded. Продуктовый код не менялся; добавлены воспроизводимая тестовая форма и runtime-сценарий. Пункты остаются открытыми, 13/42.

## Сценарий и результат

Четыре шага проходят полный продуктовый preflight: чтение исходного текста, ввод уникального RUNNER_REJECT, следующий ввод и завершающее чтение. В тестовой копии Action Fixture обработчик ПриИзменении заменяет префикс на RUNNER_CORRECTED и увеличивает счётчик. Это проверка расхождения после реального вызова, а не отказ guard до действия.

Первый шаг succeeded. Второй — failed/action_not_confirmed, execution=invoked, completed_steps заканчивается finish_edit; expected и actual различаются. Runner возвращает partial, dispatch_count=2; хвост не отправлен. Через отдельные процессы продуктового CLI выполнены recover и явный resume по сохранённому run_id. Оба сохраняют partial, исходный ответ ошибки и идентификаторы шагов/операций; новых отправок нет. Это восстановление завершённого неуспешного запуска, не новая проверка аварийного уничтожения процесса.

Независимый inspect после обоих восстановлений показывает исправленный текст и счётчик обработчика 1. Неизменность ошибки проверена полным сравнением сохранённых ответов. Для file/HTTP дополнительно прочитан журнал lifecycle: ровно один test_expect/succeeded и один test_input/failed. Для embedded доказательства — публичные ответы/ID и счётчик формы; внутренний журнал не читался.
