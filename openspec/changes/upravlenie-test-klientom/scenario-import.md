## Поддержанные преобразования

| uilog | Черновик test_* |
| --- | --- |
| FormField/inputText text | test_input/text; значение вынесено в обязательный строковый параметр |
| FormField/setCheck | test_input/check, checked=true; это установка, не переключение |

Иерархические контейнеры uilog/ClientApplicationWindow/Form/FormGroup разбираются без самостоятельного действия. Вложенная Form задаёт selector окна по своему title; это **кандидат**, требующий проверки соответствия живому UI. Для элемента сохраняются точные name/title/type. Иерархия записана отдельно для ревью; непроверенный Toolkit path не придумывается. Порядок и повторные действия сохраняются, дедупликации нет.

Таблицы, группы-карточки, open/выборы/диалоги файлов и прочие неотображённые события получают unknown_event или unsupported_event_target. Неподдержанная возможность не заменяется более общим click. Эти отказы не закрывают 1.4/4.1/4.4 и табличные задачи.

## Результат и разбор ограничений

Всегда возвращаются `version`, `status`, `draft`, `candidate_steps`, `parameter_values`, `issues`, `issues_truncated`, `targets_requiring_review`, `source_sha256`, `dispatch_count=0`, `execution_ready=false`.

- `status=draft`: полный поддержанный набор преобразован; `draft.state=draft`, у каждого шага on_error=stop и timeout_ms=10000. Это **не ready** и не гарантия однозначности/поддержки целей.
- `status=blocked`: найден неизвестный/неподдержанный узел, неоднозначная цель или превышен бюджет черновика. `draft=null`; допустимые кандидаты остаются только для ручного разбора. Нельзя выдать успешно импортированный префикс за полный сценарий.
- `status=rejected`: неверный XML/кодировка/корень/опции или превышен входной бюджет. Исполняемого черновика нет.
- Неизвестный узел сохраняется как адресуемое свидетельство: путь по индексам в исходном XML, тип, SHA-256 поддерева и код причины. Сам исходный XML остаётся у вызывающей стороны и связан source_sha256; импортёр не дублирует его содержимое/секреты в диагностике. Для полного ревью вызывающая сторона должна сохранять исходный файл в защищённом артефакте.
- Одинаковые соседние записанные цели блокируются как ambiguous_recorded_target. Отсутствующие цели не заменяются активным окном. Все остальные цели тоже перечислены в targets_requiring_review: отсутствие явной коллизии записи не доказывает единственность живой цели.
- Записанные id/uid/pid/hwnd/port/session_id/operation_id/request_id/snapshot_id/base/connectionString/user/password отбрасываются с предупреждением, без переноса значений в параметры/черновик. Неизвестные атрибуты не игнорируются. Шаблон получает только отдельно заданный policy_id, не авторизацию или базу из журнала.
- Введённые значения находятся отдельно в parameter_values; шаблон содержит обязательные `$param`, без default из записи. Это пользовательские данные для ревью, не анонимизированные значения; действующая политика обработки/хранения сохраняется. Текст, похожий на BSL, внутри inputText остаётся данными; узел исполняемого кода блокируется. Никакого eval/exec/BSL-конвертера нет.

Бюджеты: 1 MiB входа, 10000 XML-узлов, глубина 32, 100 шагов, 100 диагностических записей, длина переносимого значения до 65536, черновик до 256 KiB. Усечение диагностики помечено и не снимает блокировку. DTD/ENTITY и processing instructions не используются; обращения к файлам/сети из XML отсутствуют. Поддержан UTF-8 с необязательным BOM.
