# Запуск и восстановление локальных проверок

14.11.2026. Инструкция для проверенной локальной части Toolkit на **Windows, тонкий клиент 8.5.1.1529, файловая база**. Это не инструкция развёртывания и не запуск семи групп test_* через рабочий proxy. Публичные маршруты пока отклоняют вызовы из-за отсутствующего общего lifecycle; подключать иной исполнитель или обходить этот отказ нельзя.

## Новая изолированная база

Для каждой приёмочной серии используйте **новый каталог**, а не восстанавливайте содержимое существующей базы поверх записанных доказательств. Следующий пример копирует только согласованный тестовый источник. Блокировка исключительного доступа не даёт копировать открытый 1Cv8.1CD; при ошибке прекратите подготовку, не обходите блокировку.

```powershell
Set-Location 'C:/1C/dev/1c-mcp-toolkit'
$repo = (Get-Location).Path
$series = Join-Path $repo ('.local/task073-repeat-' + [guid]::NewGuid().ToString('N'))
$db = Join-Path $series 'db'
$run = Join-Path $series 'document'
$sourcePath = Join-Path $repo '.local/task043/db/1Cv8.1CD'
New-Item -ItemType Directory -Path $db | Out-Null
$source = [IO.File]::Open($sourcePath, 'Open', 'Read', 'None')
try {
    $target = [IO.File]::Open((Join-Path $db '1Cv8.1CD'), 'CreateNew', 'Write', 'None')
    try { $source.CopyTo($target) } finally { $target.Dispose() }
} finally { $source.Dispose() }
Get-FileHash -Algorithm SHA256 $sourcePath,(Join-Path $db '1Cv8.1CD')
```

Сравните оба SHA-256 перед запуском. При несовпадении копия не принимается. Не переносите receipt, lock-файлы или журнал операций прежнего теста в новый прогон. Копия содержит исходные служебные документы; массовое удаление T43_Required запрещено. Сам каталог исходной базы и рабочая установка не являются целями очистки.

## Подготовка и выполнение UI-проверки

Переменные предыдущего блока сохраняются в той же PowerShell-сессии. Для нового запуска создайте новый `$series`, а не повторяйте вызов в уже использованном `$run`.

```powershell
python tests/test_client/prepare_acceptance_ui.py $run
$env:PSExecutionPolicyPreference = 'Bypass' # только этот процесс и его потомки
$build = 'C:/Users/serez/.codex/skills/epf-build/scripts/epf-build.ps1'
$v8 = 'C:/Program Files/1cv8/8.5.1.1529/bin'
& $build -V8Path $v8 -InfoBasePath $db -UserName ApiProbe `
    -SourceFile (Join-Path $run 'fixture/ApiFixture.xml') `
    -OutputFile (Join-Path $run 'InputFixture.epf')
if (-not (Test-Path (Join-Path $run 'InputFixture.epf'))) { throw 'Fixture build failed' }
& $build -V8Path $v8 -InfoBasePath $db -UserName ApiProbe `
    -SourceFile (Join-Path $run 'MCPToolkit.xml') `
    -OutputFile (Join-Path $run 'Toolkit-test.epf')
if (-not (Test-Path (Join-Path $run 'Toolkit-test.epf'))) { throw 'Toolkit test build failed' }
& tests/test_client/run_runtime.ps1 -RunDir $run -DatabasePath $db -TimeoutSeconds 240
```

Проверки ThinClient/Server/HandlersExistence включены по умолчанию; `-Checks off` не использовать. При ошибке сборки дальнейший запуск прекращается. Постоянная политика Windows не меняется. В штатном harness менеджер скрыт, собственные процессы завершаются в finally. Видимый запуск нужен только для отдельно разрешённой проверки снимка менеджера; текущая инструкция его не включает.

Ожидаемые артефакты: `acceptance-plan.json`, `result.json`, `acceptance-data.json`, `manager.log`, `receipt.json`, две тестовые EPF. Каждый `ok` должен быть true; наличие файла или нулевой exit code без проверки содержимого недостаточны. В `acceptance-data.json` должна быть одна строка с номером/маркером/датой из плана и deletion_mark=false. Поле reference идентифицирует документ **только в этой базе**.

Сценарий фиксирует запись через кнопку служебной формы, а не через нативную форму документа. Открытие fixture выполняется `/Execute`, номер и дата заданы тестовой fixture, маркер введён через API тест-клиента. Разрешения ask подтверждает harness, поэтому это не пользовательская автономная приёмка. Полный вывод — [протокол 7.3](task073-partial.md).

## Остальные локальные группы

Для каждой строки таблицы нужен новый RunDir, сборка его `MCPToolkit.xml` в `Toolkit-test.epf` и тот же `run_runtime.ps1 -DatabasePath $db`. Все прогоны последовательные: один порт/клиент. Не запускать группы параллельно.

| Группа | Подготовка | Дополнения |
| --- | --- | --- |
| session | `prepare_runtime.py <RunDir>` | Harness автоматически выполняет recover при наличии old-session.txt; затем отдельный запуск с `-WithoutManager` |
| ui | `prepare_runtime.py <RunDir> --ui` | Использует ApiFixture из подготовленной тестовой базы |
| policy | `prepare_runtime.py <RunDir> --data-policy` | Собрать `tests/test_client/input_fixture/ApiFixture.xml` в `<RunDir>/InputFixture.epf` |
| unknown | `prepare_runtime.py <RunDir> --table-failure unknown` | Та же input fixture; тестовая инъекция после добавления строки |
| readback | `prepare_runtime.py <RunDir> --table-failure readback` | Та же input fixture; инъекция ошибки наблюдения |
| disconnect | `prepare_runtime.py <RunDir> --table-failure disconnect` | Та же input fixture; завершает только доказанно собственный тестовый клиент |

Для подтверждения исторических input/action/table-add используйте соответствующие флаги существующего генератора и fixture из их протоколов. Их успешный исторический результат не объявлять новым прогоном. Набор 7.3 и точные хеши EPF — [build](evidence/task073-build.json), результаты — [runtime](evidence/task073-runtime.json).

## Восстановление после сбоя

| Наблюдение | Действие | Чего результат не доказывает |
| --- | --- | --- |
| Нет свежего result.json / timeout | Сохранить manager.log, receipt и текущие состояния; дождаться finally harness и проверить процессы/порт. Не переиспользовать каталог | Отсутствие отчёта не означает отсутствие изменения данных |
| unknown после изменяющего вызова | Не повторять действие. Проверить тот же экземпляр базы запросом ниже; сохранить UI/операцию и ответ | Даже ноль строк не доказывает возможность безопасного повтора при ещё выполняющейся операции |
| Менеджер завершился, клиент может жить | Новый менеджер не получает владение автоматически. Использовать сохранённый профиль, явный attach и свежий session_id; при недоказанном владении stop отклоняется | PID, порт или receipt отдельно не дают права остановки |
| Receipt повреждён или запуск с неизвестным PID | Сохранить его и установить состояние процесса по доказательствам запуска. Не удалять receipt ради повторного start | Удаление receipt не завершает старый процесс |
| Модальное окно/несохранённые данные | Сохранить состояние; ответить только отдельным явно адресованным действием с согласованным ответом | Нельзя автоматически выбирать «Да»/«Нет» для освобождения теста |
| row_edit_pending / частичная таблица | Сохранить шаги, текущее редактирование, unknown/verification; не отменять строку и не повторять add/fill | Нет основания заявлять откат |
| stale_target / старый session_id | Новый inspect в подтверждённом сеансе и повторное однозначное разрешение цели | Старый ID нельзя перенести на похожее окно/строку |
| Следующий тест не стартует: порт занят | Определить владельца; не убивать все процессы 1С. Harness может очищать лишь собственный launcher и receipt с совпавшими PID, временем и токеном | Совпадение порта не равно владению |

Нормальный `stop` драйвера применяется только при доказанном владении. Принудительная остановка в fault injection/cleanup — тестовое средство, не рекомендация для продуктивного восстановления. Если владение не доказано, остановка остаётся отдельным ручным решением пользователя после диагностики.

### Сверка записи при неизвестном исходе

Используйте точный [запрос](../../../tests/test_client/acceptance-result.sdbl) с параметрами Номер из **acceptance-plan.json данного прогона**, НачалоГода=01.01.2026, КонецГода=01.01.2027. Выполняйте только чтение существующим инструментом запросов после подтверждения, что его соединение соответствует этой тестовой базе. Не запускайте повторно prepare/нажатие записи для получения результата запроса. Не считайте старый acceptance-data.json свежей сверкой.

Проверить все строки: 0 — запись пока не наблюдается; 1 — сопоставить номер, дату, маркер и пометку удаления; больше 1 — ошибка уникальности/области поиска. Не выбирать первую. Маркер не добавлять в WHERE: неверно заполненный документ не должен исчезнуть из результата. Запрос не заменяет наблюдение завершения операции и не разрешает автоматический повтор.

Сохранить результаты, версии, SHA-256 EPF/исходников, идентификаторы операций и query evidence до любой очистки. Проверить отсутствие слушателя 16538 и собственных процессов данного RunDir. Не публиковать пароли и строки подключения в отчёте. Контроль 7.3 завершился с нулём собственных процессов и слушателей.

Документ 7.3 оставлен в `.local/task073/db` для проверки. Для следующей серии используется новая копия; существующая копия и evidence не перезаписываются. Удаление/восстановление зафиксированной UI-записи в общей базе не проверено. Эта инструкция не разрешает удаление каталогов или документов и не закрывает соответствующее ограничение 7.1.

## Непроверенные пути

Нет инструкции успешного публичного запуска test_* через HTTP/file/встроенный HTTP: реализация lifecycle/адаптера этих маршрутов не готова. Клиент-серверная база, межмашинный RDP, дедупликация, result_expired и неизвестный исход после сетевой записи не прошли приёмку. Исправление этих зависимостей и внедрение рабочего экземпляра требуют отдельных поручений; эта инструкция их не выполняет.
