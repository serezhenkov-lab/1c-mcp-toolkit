# Замыкание BSL-зависимостей Answer42

Срез: pZayash/answer42-mcp, beta, commit `0406669a88144834bfdf6086c7040a25cb76d24c`, лицензия MIT.

Для 28 точек входа получено 138 процедур/функций (4761 строка тел с объявлениями) из 318 в модуле основной формы. Все — `&НаКлиенте`. Это минимальное транзитивное замыкание выбранных входов до двух явно заданных адаптеров, а не утверждение о минимальном объёме будущей реализации. После переработки опасных веток набор может уменьшиться.

## Полнота и границы

- [Машиночитаемый граф](evidence/answer42-dependencies.json) содержит корни, прямые вызовы, исключённые функции, интервалы исходника и SHA-256 каждого тела. SHA исходного файла проверяется отдельно.
- Экстрактор исключает комментарии и строки с сохранением смещений, учитывает регистр BSL, рекурсию и транзитивные вызовы. Для каждого локального вызова проверяет наличие в наборе или на границе адаптера.
- В наборе нет динамического `Выполнить`, `Вычислить`, `ОписаниеОповещения` и подключения обработчиков по строковому имени. При смене ревизии этот вывод надо перепроверить.
- Замыкание включено в отдельную EPF и прошло платформенную проверку `ThinClient,Server,HandlersExistence` и сборку. Заглушки прикладных метаданных: 0. Общие модули, объектный модуль донора, его формы и дополнительные компоненты не требуются для компиляции этого набора.
- Контекст: две переменные `ТестируемоеПриложение` и `ТекущийМетодЗапросаMCP`. В Toolkit первая принадлежит служебной форме, вторая заменяется контекстом текущей операции.
- Граница 1: `Лог(Сообщение)` → существующее журналирование Toolkit. В проверочной EPF пустая процедура: функциональность логирования этим не проверяется.
- Граница 2: `ОтправитьСобытиеПрогрессаMCP(Метод, Фаза, ДополнительныеДанные = Неопределено)` → существующий lifecycle/прогресс. В проверочной EPF пустая процедура; WebSocket, request envelope и состояние соединения донора не включены.
- Запуск, подключение, отключение и stop донора исключены осознанно. Прототип использует конструктор `ТестируемоеПриложение(host, port)`, `УстановитьСоединение` и `РазорватьСоединение` непосредственно; запуск и завершение осуществляет отдельный скрипт по дескрипторам только созданных им процессов. Это не реализация lifecycle Toolkit.
- Не включены WebSocket-мост, Python-сервер, RAG, создание базы менеджера, выполнение произвольного кода и запросов донора. Текстовые ссылки на RAG в сообщениях исходного UI-кода не являются вызовами, но должны быть удалены при адаптации.
- BSL Testpilot в перенос не входит: его EPF обслуживает код/запросы/метаданные; UI реализован в Python через протокол. Для него набор переносимых BSL-зависимостей пуст. Python и AGPL-код не копируются в Toolkit; используются результаты анализа поведения.

## Что ещё обязательно изменить при адаптации

Замыкание содержит исходные алгоритмы, включая известные несовместимости: первый найденный элемент, busy-wait, закрытие панели сообщений, альтернативные мутации после неподтверждённого ввода, скрытую отмену редактирования, ошибочные предположения о методах таблицы. Их наличие в исследовательском пакете не разрешает перенос без изменений. Обязательные замены описаны в [исследовании](research.md) и [протоколе API](preflight.md).

Все 138 функций скомпилированы, но в базе не выполнены все их ветви. Выполнение проверялось на низкоуровневых API и сериализаторе выбранного окна. Сборка не доказывает существование поздно связываемых методов объектов — именно так обнаружено отсутствие `ПолучитьСтроки()`.

## Платформенные зависимости

Конструкторы внутри извлечённого набора: ЗаписьJSON, Массив, Соответствие, Структура, ЧтениеJSON. Дополнительно прототип подключения создаёт ТестируемоеПриложение. Динамическое обращение к свойствам тестируемых объектов относится к платформенному UI, а не к метаданным бизнес-конфигурации.
