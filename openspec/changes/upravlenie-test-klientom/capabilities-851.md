# TASK-011/1.4 — API установленной 8.5.1.1529

Дата: 13.11.2026. Проверены локальная справка установленной платформы и отдельные диагностические EPF. Код Toolkit и рабочая установка не изменялись. Пункт 1.4 остаётся открытым: точный API найден, но положительный runtime-результат открытия ячейки не получен.

## Среда и доказательства

- Менеджер и клиент: `C:\Program Files\1cv8\8.5.1.1529\bin\1cv8c.exe`, Windows, тонкий клиент, `/TESTMANAGER` и `/TESTCLIENT -TPort16539`.
- Сначала использована прежняя изолированная база `controlled85`, ApiProbe, интерфейс Такси. Затем создана отдельная файловая копия `.local/capabilities-851/db85ui`; только в ней установлен интерфейс Version8_5, совместимость Version8_5_1 и добавлен диагностический справочник ProbeItems с предопределённым Target (`API_CELL_TARGET`). Рабочая база не использовалась.
- Фактический интерфейс клиента прочитан самой fixture: `Версия 8.5|ProbeItems`. Роль ApiProbeAdmin имеет `setForNewObjects=true`; добавление Read/View скриптом роли не изменило права, поскольку они уже соответствовали умолчанию. Гипотеза об отсутствии прав не подтверждена.
- [Справка и перечень методов таблицы](evidence/capabilities-851/local-help.json): извлечены из `shcntx_ru.hbk` именно установленной сборки, сохранён SHA-256. В HBK смешаны UTF-8 и Windows-1251; кодировка определялась отдельно для каждой страницы.
- [Прогон Такси](evidence/capabilities-851/runtime-taxi.json), [прогон Версия8_5](evidence/capabilities-851/runtime-ui85.json), [матрица](evidence/capabilities-851/capabilities.json), [исходники диагностики](evidence/capabilities-851/probe-source.zip).
- Локальный запуск: `.local/capabilities-851/run.ps1`. Скрипт открывает два собственных процесса и закрывает только их в finally; остановка чужих сеансов по имени/PID/порту не применяется. База и артефакты сохранены для разбора, сеансы завершены.

## Существенные наблюдения

1. Видимая обычная группа без карточки/гиперссылки также принимает Нажать() без исключения. В первом варианте пустая невидимая группа отклоняла вызов именно по невидимости. Следовательно, отсутствие исключения не доказывает нужный тип группы или выполненное действие. Для click_group остаются явные проверки состояния и readback.
2. Открытие значения — **метод поля колонки, не таблицы**. Условия из локальной справки: интерфейс Версия8_5, значение-ссылка, строка вне редактирования. Проверены текст ячейки `API_CELL_TARGET`, отсутствие редактирования, выделение строки и активация поля. Открыть() завершился без исключения; снимок после него содержал только fixture и начальную страницу. Ожидаемая форма и её поле Наименование не найдены.
3. Отдельная контрольная кнопка fixture вызывает обычный ОткрытьФорму для той же ссылки. Она открыла `Справочник.ProbeItems.ФормаОбъекта`, заголовок `API_CELL_TARGET (Probe items)`, Наименование=`API_CELL_TARGET`. Это контроль исправности стенда, а не успешный тест API ячейки и не разрешённый fallback Toolkit. Причина расхождения штатного тестового API пока не установлена; ошибка платформы не объявляется доказанной.
4. ПолучитьПредставлениеДанных() у поля колонки вне редактирования возвращает ошибку неподходящего состояния. ПолучитьТекстЯчейки("СтрокиСсылка") успешно читает значение. Снимок сохраняет ошибки отдельных полей, не выдаёт их за пустые значения.

## Проверки и оставшиеся действия

Диагностические EPF прошли платформенную проверку ThinClient/Server/HandlersExistence и сборку на 8.5.1.1529. Эти проверки относятся к пробам; Toolkit не собирался и его интеграционная приёмка не выполнялась. Ранние ошибки диагностического кода/селектора исправлены; итоговый протокол сохраняет неуспех проверки результата открытия ячейки.

До закрытия 1.4 нужен положительный воспроизводимый результат Открыть() для ссылочной ячейки либо установленная причина ограничения этой сборки/состояния формы. Проверить влияние свойств и режима таблицы на кнопку открытия, при необходимости сопоставить с более новой отдельно установленной сборкой. Текущие доказательства запрещают объявлять action.open_cell_value поддержанной. Реализация TASK-014/4.4 и TASK-015/5.4 этим исследованием не выполнена.

Установлено различие по режиму строки: обычное открытие редактируемого поля работает, новое поведение вне редактирования на этой fixture не воспроизводится. Автоматически начинать редактирование вместо запрошенного открытия вне редактирования нельзя: это другой сценарий и побочные эффекты. Причина расхождения с описанием справки не установлена окончательно; 1.4 остаётся открытым, capability вне редактирования остаётся unverified. Для завершения нужен разбор оставшихся условий отображения кнопки/событий открытия либо подтверждение ограничения сборки на минимальном примере.


## История: преждевременное закрытие 1.4 (отменено)

Дополнительная проба события Открытие: обработчик только отмечает вызов и не меняет СтандартнаяОбработка. Вне редактирования обработчик не вызывается (event-outside.json); при редактировании фиксируется OPENING:Да, открывается объект и читается API_CELL_TARGET (event-edit.json, opening-event.txt). Исходники — event-probe-source.zip. Ошибки чтения исходной формы после открытия относятся к её недоступности, а не к отказу открытия объекта.

На проверенной fixture 8.5.1.1529 эффект локализован до доставки события открытия вне редактирования: это не отказ обработчика от стандартной обработки, не отсутствие ссылки и не невозможность открыть объект. Явные варианты гиперссылки и ТолькоПросмотр ранее результата не изменили. Внутренняя причина платформы не установлена; универсальный дефект для всех таблиц не утверждается.

Пункт 1.4 закрыт **как проверка API и матрицы ограничений**, а не как устранение расхождения со справкой. Политика v1 для action.open_cell_value на этой сборке — unsupported (проверенный путь вне редактирования не даёт результата); метод Открыть существует и обычное открытие в редактировании работает. Не применять этот контроль как fallback: начало редактирования меняет сценарий. Для других форм/сборок — unverified до отдельного положительного теста. Новое основание для включения операции проверяется в 5.4; задача остаётся открытой. Предыдущие записи об открытом 1.4 и unverified сохранены как история расследования и заменены этим итогом.


Уточнение пользователя после проверки событий: **1.4 снова открыт**. Отключение возможности и отрицательная матрица не являются завершением исследования. Прежняя отметка о закрытии отменена; причина расхождения со справкой ещё требует установления.


## Текущий итог: 1.4 открыт, исследование остановлено без установленной причины

По уточнению пользователя отключение функции не закрывает 1.4. Статус action.open_cell_value возвращён в unverified; отсутствие метода не заявляется. Отрицательные прогоны не доказывают универсальную неподдержку операции платформой. При этом адаптер Toolkit ещё не реализован и не получает supported.

[Минимальный воспроизводимый пример](evidence/open-cell-minimal/README.md) подтвердил отказ на форме с одной строкой и одной ссылочной колонкой, без обработчиков открытия и выбора. Текущая ячейка подтверждена через ПолучитьТекстЯчейки() без параметра, редактирование отсутствует, КнопкаОткрытия=true. XML 2.21 исключает сохранение старого формата 2.17 как достаточное объяснение. Сам исполняемый файл имеет FileVersion/ProductVersion 8.5.1.1529.

Современный метод КлиентскоеПриложение.ТекущийВариантИнтерфейса() на клиенте и сервере вернул «Версия 8.5». Устаревший глобальный метод на клиенте вернул «Такси», хотя на сервере также сообщил «Версия 8.5». Поэтому прежнее серверное чтение не заменяет проверку современного клиентского API; обнаруженное расхождение устаревшего API пока не объяснено. Явный /i85 также не изменил результат Открыть().

[Официальные изменения 8.5.1](https://dl03.1c.ru/content/Platform/8_5_1_1150/1cv8upd_8_5_1_1150.htm) описывают нужное поведение, но называют метод ТестируемаяТаблицаФормы.Открыть(). Отдельная runtime-проба этого имени дала «Метод объекта не обнаружен». Метод тестируемого поля существует и соответствует локальному синтакс-помощнику. [Официальная методика перехода](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/i8106027.htm) подтверждает параметр /i85.

Подтверждённого объяснения, устраняющего расхождение, не получено. Невызов Opening показывает наблюдаемое поведение конкретной пробы, но не доказывает внутреннюю причину в диспетчере событий платформы. На этом исследование приостановлено по согласованному пользователем принципу «если результата не будет — идём дальше»; 1.4 остаётся открытым. Независимые задачи могут продолжаться; 5.4 нельзя принимать по успешному открытию в режиме редактирования вместо заявленного сценария. Новая проверка оправдана при появлении исправления платформы, другого подтверждённого примера или новых данных, а не повторением тех же условий.
