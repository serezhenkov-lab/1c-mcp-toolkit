## Реализация

- Общий владелец embedded размещён в существующем runtime EPF: `1c/runtime/embedded_lifecycle.bsl`. Это общий журнал операций без UI API. Адаптер `embedded_test_adapter.bsl` передаёт команды существующему менеджеру и принимает его события/результаты. Дополнительный сервис не требуется; legacy execute_code не переводится в новый контракт автоматически.
- REST POST `/api/test_*` и native MCP `tools/call` используют одного владельца; семь схем публикуются в `tools/list`. Схемы берутся из Python INPUT_SCHEMAS генератором `1c/runtime/generate.py`; ключевые ограничения проверяются до admission. Старые 344 GENERATED-блока не изменены. `--check` проверяет актуальность новых фрагментов.
- Ключ повторного запроса ограничен каналом; отпечаток включает tool и канонические аргументы с defaults. Admission и running сохраняются до вызова исполнителя. Повтор возвращает тот же ID, другой запрос с тем же ключом даёт request_conflict. Статус операции читается из журнала без ожидания UI и разрешения. REST возвращает Cache-Control: no-store.
- Подтверждения используют существующие формы и проверки 1С: awaiting_approval/running, отказ с отсутствием исполнения, конечный результат. Асинхронное ожидание UI не удерживает первоначальный HTTP-запрос. Это не обещание прерываемости синхронного платформенного вызова в клиентском потоке.
- Файловый restart теперь передаёт снимок текущего подключения так же, как зарегистрированный источник. Восстановление остаётся после существующей проверки nonce; старый файловый формат без снимка совместим. Найденная ошибка: EPF из файла после restart переходила на порт 6003 вместо текущего 17657.

## Хранение и ограничения общего владельца

Реализация и ограничения принадлежат TASK-002 изменения `rezhimy-podtverzhdeniya-i-izolyatsiya-chatov`, не отдельному UI-реестру. Журнал — append-only JSONL с контрольной SHA256 и последовательной ревизией; блокировка FileStream запрещает второго писателя. На 8.5 вычисление SHA256 выполняется серверной функцией без контекста, файловый владелец остаётся клиентским. По умолчанию путь — РабочийКаталогДанныхПользователя()/MCPToolkit/lifecycle; внутренний trusted bootstrap может задать каталог явно. Стенд использовал явный путь, стандартное размещение отдельно не проверялось.

Пределы: 10 000 ключей, 100 активных операций, 64 MiB журнала; admission прекращается после 60 MiB, ограничение результата — консервативная оценка 4 MiB. После process-kill прежние queued/running/awaiting_approval становятся unknown и не повторяются. Повреждение/оборванный хвост закрывает исполнение, автоматического исправления нет. Закрытие файлового буфера не является гарантией сохранности при потере питания ОС.

TTL результата — 24 часа; истёкший результат не выдаётся, ключ остаётся занят. Это относится и к вложенным сохранённым статусам. **Физическая компактация и удаление старых payload из append-only файла пока не реализованы**: файл ограничен квотой, но логический result_expired не означает физического удаления. Это оставшаяся работа общего владельца, а не ослабление требования хранения.

При включённой точной анонимизации test_* возвращают operation_result_policy_not_ready до admission и до выдачи сохранённого результата. Политика nested UI data с сохранением служебных ID ещё не подключена в BSL; положительный сценарий анонимизации не заявлен. Полный 6.3 остаётся открытым.

## Проверки

Стенд: Windows, тонкий клиент **8.5.1.1529**, отдельная файловая база `.local/embedded-lifecycle/db`, пользователь ApiProbe, HTTP 17657 и TESTCLIENT 16541. Профиль и каталог журнала задаёт тестовая оснастка; ответы на реальные формы разрешения программно подаются той же оснасткой. Это runtime-проверка, не ручная приёмка и не клиент-серверный/RDP прогон.

- `run_public_probe.py --embedded`: запуск клиента, windows/activate, expect с доступным running, финальный timeout, повтор/defaults/конфликт; негативные input/table и вызов open. Успех произвольного открытия формы не утверждается.
- `run_embedded_contract.py`: схемы и вызовы **всех 7 групп native MCP**, **70 REST случаев** в сравнении с Python valid_request: границы, типы, регистр, неизвестные свойства, пустые селекторы. Вызовы с несуществующим session_id доказывают admission/контракт, не успешное действие UI.
- `run_embedded_probe.py`: awaiting_approval→отказ/согласие, session detach с отказом, дедупликация, чужой канал, invalid_params, fail-closed анонимизация, result_expired без переисполнения и конфликт после TTL; публичный restart_1c_session с восстановлением endpoint и TESTMANAGER, сбросом session_allow, unknown прерванного expect и повтором без исполнения. Последний прогон завершился без ручного вмешательства. Ранние неудачные пробы сохранены отдельно; их завершение после ручного перезапуска не считается сквозным успехом.
- `run_embedded_recovery.py`: принудительное завершение собственного процесса менеджера при running, восстановление unknown с прежним ID без повторного запуска; истечение результата внутри двух вложенных сохранённых статусов.
- Платформа отклонила второй пишущий FileStream. На копии журнала проверен оборванный хвост: отказ загрузки без исполнения.
- Итоговая EPF из рабочих исходников собрана с проверками **ThinClient, Server, HandlersExistence**. BSL LS: 1 модуль, 6535 диагностик, 752 Error вне изменённых строк, **0 Error на 442 изменённых строках**. Это не утверждение чистоты всего модуля.
- Регрессия Python адаптера: **7/7**. OpenSpec strict для обоих изменений и проверка синхронизации генератора прошли.

Доказательства: [архив](evidence/embedded-lifecycle-runtime.zip), [SHA256-манифест](evidence/embedded-lifecycle-manifest.json). Полные локальные журналы и исходники оснасток сохранены в `.local/embedded-lifecycle`.

Остаются: положительная embedded-анонимизация и полная матрица политик/отказов/квот, физическая очистка журнала, штатное восстановление доверенного профиля вне тестовой оснастки, клиент-серверный/RDP режим и пользовательская приёмка. Общие пункты очереди 1 остаются открытыми.
