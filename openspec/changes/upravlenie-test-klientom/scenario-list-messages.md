# TASK-021 — продуктовый сценарий выбора из списка и сообщений

17.11.2026. Из актуального остатка выбрана доступная нетабличная ветка: выбор по отображению списка и наблюдение сообщений. Наблюдатель, табличная идентичность и новая запись uilog не требуются. Основания: внутренний ввод в [TASK-014/4.1](task041-runtime.md), сообщения/ожидания в [TASK-013](task013-runtime.md) и [inspect coverage](task034-runtime.md). Старые наборы не повторялись; проверялось новое сочетание в продуктовом поставщике/CLI.

## Реализованный объём

В реестр добавлены test_input:select:list:none, test_inspect:messages:scalar:none и test_expect:message:scalar:none для трёх маршрутов файловой 8.5.1.1529. Теперь **15 capabilities на HTTP, файловом мосте и embedded**. Исполнитель, поставщик, BSL и EPF не менялись. Добавлен сценарий приёмки; локальные тесты проверяют preflight нового плана/маршрутов, отсутствие табличной capability и обязательность scope для новой мутации.

Новые возможности не отменяют ограничения драйвера: выбор только при полном однозначном списке, без слияния одинаковых отображений; сообщения — текущий доступный снимок, не полная история. Закрытая панель и неполный/неизвестный источник не доказывают отсутствие сообщений. Эти старые отрицательные ветви не прогонялись повторно. Отображение списка не отождествляется со значением поля.

## Новая цепочка

Через отдельный процесс продуктового CLI, живой контекст и явную локальную политику точных команд:

1. Выбрать CHOICE_ALPHA — подтверждённое значение A.
2. Выбрать CHOICE_BETA — подтверждённое значение B, before=A.
3. Нажать кнопку Проверить один раз, чтобы сформировать сообщение для новой проверки.
4. Прочитать сообщения через test_inspect/messages.
5. Подтвердить ACTION_CLICK через test_expect/message.

Нажатие — зависимость нового сценария сообщений, а не повтор отдельной принятой проверки кнопки. Два последовательных выбора — разные явно заданные команды, не retry. Документы не создаются; изменяется только одноразовая форма фикстуры.

| Маршрут, файловая 8.5.1.1529 | Шаги | Утверждения |
|---|---|---|
| HTTP-прокси | 5/5 | 6/6 |
| Файловый мост | 5/5 | 6/6 |
| Embedded HTTP | 5/5 | 6/6 |

На каждом маршруте подтверждены complete=true и один кандидат каждого выбора, соответствия CHOICE_ALPHA→A/CHOICE_BETA→B, доступность/полнота снимка сообщений и matched=true для ACTION_CLICK. По пять уникальных operation_id и пять отправок на сценарий. В общих SQLite-журналах HTTP/file отдельно read-only подтверждены по три ожидаемые succeeded-мутации: два выбора и нажатие. Для embedded сохранены публичные ответы общего lifecycle; SQLite ему не приписывается. Документы до/после неизменны, все собственные процессы завершены.

Два новых локальных теста успешны. Прежние подтверждённые сценарии восстановления/ввода, общий unit-набор и сборка EPF не повторялись. Проверены AST, OpenSpec strict и diff-check; матрица обновлена по новым доказательствам.
