# Нативный сценарий и очистка 7.1/7.3/7.5 — 17.11.2026

Достигнут новый рубеж: один воспроизводимый сценарий нативной формы документа с адресной очисткой выполнен без ручного контроллера на всех трёх маршрутах **файлового** стенда 8.5.1.1529. Результат — **48/48 утверждений**. Это не полная приёмка 3/6 сред: остальные обязательные отрицательные/табличные сценарии не покрыты этим запуском. Формальная полная матрица остаётся 0/6, отметки 13/42 сохранены.

## Сценарий и идентичность базы

Использован существующий `Документ.T43_Required`, обязательный строковый реквизит `ОбязательноеПоле`, проведение запрещено. Основа — остановленный подготовленный стенд `.local/native-document-20261116T121346/http/db` с ранее подтверждёнными InteractiveInsert/Edit. Для каждого маршрута создана новая копия 1Cv8.1CD; исходная база не изменялась. Новые метаданные и права не добавлялись.

Тонкий клиент и менеджер запускаются в одной копии; штатный attach проверяет строку подключения процесса клиента. Серверный запрос проверяет путь этой же базы. Паспорт содержит session_id, base_id, версию 8.5.1.1529 и SHA-256 EPF. Использована обычная `Toolkit-production.epf` предыдущего этапа file-recovery, без fault hooks. Fixture открывает начальное окно; запись производится только штатной командой нативной формы документа.

Порядок автоматического запуска:

1. Получить полный исходный набор документа, сохранить все ссылки/номер/дату/маркер/пометку, убедиться в отсутствии уникального маркера прогона. При 1000 строках остановиться: полнота не доказана.
2. Открыть список, выбрать точную команду `ФормаСоздать`, получить дерево нативной формы. Ввести дату 17.11.2026 12:00:00. Номер оставить штатной автонумерации; проверку ручного номера/модальности не повторять.
3. Нажать `ФормаЗаписать` с пустым обязательным полем: получить сообщение обязательности и подтвердить неизменность исходного набора. Этот шаг включён заново как обязательная часть связанного TI-05, не как отдельный повтор прежней диагностики.
4. Ввести свежий `NATIVE_CLEANUP:<UUID>`, подтвердить фактическое значение, выполнить одно предусмотренное сценарием нажатие записи. Сопоставить полный набор до/после без фильтра по маркеру: ровно одна новая ссылка, ожидаемые дата/маркер, непустой автоматически назначенный номер, отсутствие пометки удаления; прежние строки неизменны.
5. Закрыть сохранённую форму через `test_action/close`. Удалить только новую ссылку и проверить полное равенство выбранных данных исходному набору, отсутствие ссылки/маркера и восстановленный серверный контекст.

UI-операции вызываются через публичные test_*, ID операций и терминальные ответы сохранены. Нажатия не повторяются при тайм-ауте, failed или unknown. После записи выполняется чтение фактических данных даже при неоднозначном ответе, но автоматического повторного нажатия нет. На неподтверждённом шаге сценарий останавливается, выделенная база и доказательства сохраняются для сверки; никакой массовой очистки в `finally` нет.

## Адресная очистка

У тестовой роли нет Delete. Только служебная серверная очистка выполняется в привилегированном режиме: проверяются ожидаемый путь тестовой базы, новая ссылка, не входившая в baseline, и точный маркер. В отдельной транзакции вызывается `ПолучитьОбъект().Удалить()` для одной ссылки; при ошибке транзакция отменяется, исходный режим восстанавливается. UI-ввод и запись не получают привилегированный режим этой процедуры.

На каждом маршруте подтверждено **9 → 10 → 9**, полное равенство исходных строк по выбранным полям, удалённая ссылка/маркер отсутствуют, privileged=false и transaction=false. Это очистка зафиксированного документа, не откат UI-операции: журнал lifecycle, логи и нумерация не возвращаются в прежнее побайтовое состояние. Старые документы и исторические тестовые базы не чистились.
