## Реализация

- `normalize_query_result(result, context, contract)` принимает структурированный ответ существующего execute_query: `success`, `data`, `schema.columns[{name,types}]`. Форматированные JSON/TOON-строки не разбираются. Происхождение, база, обработка данных и границы чтения задаются доверенным сборщиком; этот API не предназначен для публичного приёма утверждений пользователя о полноте.
- `context` содержит поля source контракта, кроме вычисляемых kind/status/coverage/normalization_error, и `response_complete: bool`. Только целиком полученный успешный ответ с известным лимитом и меньшим числом строк может получить complete. Ровно лимит/явное усечение/незавершённая доставка дают unknown. Неверный источник сохраняет отказ.
- Примитивные типы и заполненные ссылки справочников/документов приводятся к типизированным ячейкам. Десятичные числа принимаются как Decimal или точное целое; float отклоняется. Колонка с неоднозначным набором нативных типов не получает догаданный тип. Неподдержанные значения и null без явной политики дают причину недоступности.
- `compare_query_results(request)` проверяет контракт, источники, охват, точность, схему, порядок и ключи; сравнивает bag/keyed/ordered. Дубли сохраняют кратность. Нет подбора похожих строк или приведения bool к числу. Схема сопоставляется по именам колонок.
- Возвращаются глобальные счётчики и ограниченный структурированный diff. 100 записей/256 KiB ограничивают выдачу diff после вычисления всех счётчиков; превышение входного бюджета не превращается в равенство. Результат отделён от входных объектов, исключения не выводят содержимое данных в лог.

Модуль не выполняет I/O, запросы, команды или повторы; не регистрирует новый транспорт/журнал. Данные и diff сохраняют требования действующей изоляции и обработки данных. Новый обход анонимизации не добавлен, разработка анонимизации отложена.
