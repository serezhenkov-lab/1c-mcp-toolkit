## Дополнительные выходные поля

Без новых публичных инструментов и второго журнала. Входные схемы семи test_* сохраняются.

- `test_inspect/tree.data.editor`: `status`, `reason`, `active_element`, `editing`, `text`, `column`, `choice_list`. Измерения имеют `{available,value,reason}`; unavailable не заменяется пустой строкой или false. Читается только текущий элемент единственной формы; при изменении активного элемента результат отвергается. Текст максимум 16384 символа; весь editor максимум 64 KiB. Состояние открытого списка теперь читается штатным API поля ввода; для других видов поля возвращается not_an_input_field, при ошибке — property_read_failed. См. queue2-current.md. Чтение не переключает фокус, не завершает редактор и не меняет строку.
- `data.diagnostics`: `operation_id`, `before`, `after`, `last_confirmed_step`, `progress`, `errors`, `artifacts`, `complete`, `reason`. До/после — ограниченные снимки состояния/приложения; ошибки команды и наблюдения раздельны, нативная информация об ошибке приложения не выводится из текста пользовательского сообщения. Исходный execution/verification сохраняется при сбое дополнительной диагностики. Сырые исключения приложения с потенциальными секретами не публикуются.
- Диагностика максимум 64 KiB в прежнем общем лимите результата. `progress` отражает подтверждённые шаги текущей операции и время; это не поток промежуточных событий. `artifacts` ссылаются на inline JSON-pointers внутри результата того же operation_id; отдельного файлового хранилища и обхода канальной изоляции нет. Автоматический снимок не производится: get_screenshot остаётся явной операцией.
- `get_screenshot(target=test_client,session_id=...)`: драйвер проверяет действующий сеанс, PID/CreationDate и endpoint; компонента повторяет проверку процесса, session/desktop и однозначности главного окна. При неоднозначности, скрытости, смене процесса или недоступности возвращается screenshot_target_unavailable без изображения менеджера. Успех содержит идентичность процесса/окна и session_id. Регион/сетка/highlight используют координаты клиента; selectors формы менеджера запрещены. Legacy/toolkit использует прежний CaptureWindow.

## Принятые и отклонённые доказательства

- Публичный inspect прочитал незавершённый буфер поля и текущей ячейки/колонки; состояние до/после чтения совпало. Контролируемая смена колонки между чтениями дала `active_editor_changed`. Это тестовая инъекция в копии EPF; наблюдателя в Toolkit нет.
- 20000 символов в редакторе дали `value_limit`. Диагностический блок ограничен 64 KiB с резервом в общем лимите результата; переполнение не изменяет подтверждённый исход действия.
- Кнопка-счётчик проверяет ровно одну мутацию: normal, ошибка наблюдения, исключение диагностики, переполнение диагностики. Повтор request_id сохраняет operation_id и значение счётчика. Другой канал не получает diagnostics/артефакты операции.
- Нативный `ПолучитьТекущуюИнформациюОбОшибке()` подтвердил ошибку приложения после отдельной команды fixture. Наличие ошибки приложения не выводится из сообщения пользователю.
- В первом embedded-прогоне автоматическая проверка модального PNG дала ложноположительный результат. **Визуальная проверка отклонила `embedded/client-error-modal.png`: в нём видны пиксели перекрывающего приложения. Этот снимок не является успешным доказательством 6.4.**
- Исправлен экранный fallback внешней цели: проверяются владелец окна, геометрия, перекрытия чужими окнами до/после BitBlt и foreground; отказ любого слоя запрещает возвращать изображение. Legacy/toolkit сохраняет прежний маршрут.
- После исправления перекрытие модального окна чужим процессом возвращает отказ без PNG. Положительная модальная проверка всё ещё отказана: `ERROR:target:modal_not_in_frame`. Перечень окон и геометрия сохранены; при наблюдаемом порядке окон активная модальность отсутствует среди подтверждённых слоёв кадра. Перестановка собственных окон/размещение диалога внутри кадра положительного результата не дали. Проверка не ослаблена ради закрытия пункта.
- Первый HTTP-прогон обнаружил потерю capture_target/session_id в whitelist передачи результата. Исправлены обе границы: 1С callback и Python CommandResult/server, а также текстовые метаданные MCP. Ранние неудачные прогоны сохранены отдельно.
