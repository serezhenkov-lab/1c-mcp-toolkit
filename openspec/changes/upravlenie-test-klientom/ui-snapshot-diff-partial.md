# 12.1 — доступный diff UI-снимков, 16.11.2026

Реализован `onec_mcp_toolkit_proxy/ui_snapshot_diff.py`, функция `diff_ui_snapshots(before, after)`. Это самостоятельный компаратор публичных результатов `test_inspect/tree`, без транспорта, действий UI, повторов команд и наблюдателя. Публичный endpoint пока не добавлен. Требования TE-05 не сокращены; 12.1 остаётся открытым.

## Контракт

Вход каждого снимка — `{binding, result}`, где result — успешный публичный ответ tree, а binding создаёт доверенный сборщик в момент чтения. Обязательны непустые строки owner, channel_id, base_id, session_id, generation, window_id, scope, data_policy_id. Произвольные пользовательские метки не доказывают идентичность. Сборщик должен получать оба снимка через один точный зарегистрированный window_id, а не повторный поиск по заголовку.

Для текущего реестра разрешён только `generation_proof=registry_window_id` и `generation=window_id`: инвалидация целей удаляет реестр, новая регистрация получает новый UUID. Это ограниченное доказательство поколения реестра, а не наблюдение жизненного цикла нативной формы. Корневые element_id должны совпасть; смена корней/типа общего ID, сеанса, поколения, владельца, канала, базы, области или политики данных делает снимки несопоставимыми. Продуктовая выдача доверенной привязки ещё не реализована; пока контракт используется отдельным сборщиком в проверке.

Сопоставление строго по element_id. Сравниваются name, title, visible, enabled, read_only, editing, а при полном структурном охвате — parent_id. Текст, путь и позиция не используются как идентичность. Текущие значения полей не входят в tree и не сравниваются. Строки таблиц, командный интерфейс, командные панели, дополнения таблиц и изображения явно исключены.

Добавление/удаление разрешено только при complete=true, truncated=false, единственной полной записи form_tree в coverage обеих сторон и отсутствии unsupported-узлов. Иначе отсутствующий ID — unobserved; общие доступные свойства всё равно сравниваются. unavailable-свойство не заменяется пустотой и не доказывает равенство.

Выход содержит status (`equal`, `different`, `partial`, `unavailable`), трёхзначный equal, reason, sources, исходный coverage, added/removed/changed, unavailable_properties, unobserved_ids, глобальные counts и diff_truncated. `partial/equal=false` означает подтверждённое различие доступных свойств при неполном наблюдении; `equal=null` — отсутствие доказательства равенства или различия. Даже status=different относится только к объявленной области, недоступность отдельных свойств сохраняется.

Лимиты: вход до 2 MiB JSON, до 5000 узлов на сторону и глубины 32. Представление diff — суммарно до 100 записей и 250 KiB содержимого записей; counts и вывод вычисляются до усечения. Coverage и provenance в этот лимит представления не входят. Исторические снимки можно сравнивать после expires_at: это не разрешение использовать просроченные ID для действий. Атомарность двух чтений и полная история изменений не заявляются.

## Новая проверка

`tests/test_ui_snapshot_diff.py`: 12/12 локальных тестов — равенство доступной структуры, изменение свойства, одинаковые подписи разных ID, неполнота, неизвестный coverage, unavailable, чужая привязка, смена корня/типа, дубли ID, лимиты и повреждённый вход. Структурное добавление/удаление проверено на синтетических полных деревьях, не объявляется подтверждённым для всех форм 1С.

`tests/test_client/run_ui_snapshot_diff.py`: новый отдельный файловый стенд, 8.5.1.1529, HTTP proxy, существующая проверенная production EPF. Сборка EPF не требовалась: BSL и нативная компонента не менялись. Рабочая установка не обновлялась. Использованы только определения вспомогательных функций прежней обвязки, старые проверки не исполнялись.
