# TASK-015/5.2 — добавление без заполнения и клиентского адаптера

13.11.2026. Реализована ограниченная часть 5.2: внутренний `test_table/add` без `values`. **5.2 в целом остаётся открытым.** Заполнение, удаление и подтверждённый идентификатор новой строки не реализованы.

## Поведение

Команда проходит существующую последовательную очередь и проверку разрешений основной формы, включая повторную проверку перед мутацией. Проверяются однозначная таблица, её видимость, доступность и режим только просмотра. Если таблица уже редактируется, возвращается `row_edit_pending`, `execution=not_started`, `editing=true`: ни завершения, ни отмены редактирования нет.

В допустимом состоянии вызывается ровно один `ДобавитьСтроку()`. После возврата сохраняются `execution=invoked`, `completed_steps=[add]`, инвалидируются старые UI-цели и читается `ТекущийРежимРедактирование()`. Строка автоматически не завершается. Независимая идентичность недоступна, поэтому итог — `incomplete_search`, `verification=not_confirmed`, `identity.status=unavailable`. `verification_scope=invocation_and_editing_state` описывает только область наблюдения: даже при `editing=true` успешное создание именно новой строки не заявляется. Повторять такую команду автоматически нельзя.

`add` с переданным `values` отклоняется до мутации как `incomplete_search`, включая пустой массив: заполнение новой строки без независимого подтверждения её идентичности не выполняется. Остальные действия `test_table` пока возвращают `unsupported_operation`. Публичные транспортные маршруты остаются TASK-016; здесь добавлен внутренний исполнитель, без обхода разрешений.

Методы `ДобавитьСтроку()` и `ТекущийРежимРедактирование()` подтверждены каталогом API 8.5; фактический вызов проверен на 8.5.1.1529. Нативные объекты формы тестируемого клиента не читаются, клиентский адаптер не внедрён.
