# 1c-mcp-toolkit / TASK-006 — Понятные ошибки и состояние подключения

## Цель и ожидаемый результат

Очередь 2. Показывать источник ошибки и подтверждённую готовность среды.

## Требования и сценарии

[RD-01](../specs/runtime-diagnostics/spec.md#rd-01), [RD-02](../specs/runtime-diagnostics/spec.md#rd-02). Сценарии этих требований проверяются шагами карточки.

## Границы работы

Только указанная очередь сокращённого объёма [proposal](../proposal.md). Исключённые пользователем функции не добавляются. Испытания — на свежих данных выделенной тестовой среды, без исторической очистки.

## Затрагиваемые объекты и технические указания

Точные точки EPF/proxy и ограничения GENERATED BSL — в [research](../research.md); поведение и совместимость — в [design](../design.md). Работающая установка и её настройки не меняются; разработка и проверки ведутся отдельно.

## Зависимости

[TASK-002](TASK-002.md)

## Критерии приёмки и проверка

Показывать источник ошибки и подтверждённую готовность среды. Подтвердить сценарии требований; отдельно зафиксировать автоматические проверки, сборку, выполнение в 1С и пользовательскую приёмку. Недоступную проверку не считать успешной.

## План выполнения

Раздел 4 в [едином плане](../tasks.md).

- 4.1 Унифицировать ID, контекст и причины ошибок. Проверить классификацию по источнику, `error=null` при успехе и отсутствие секретов в дополнительных полях. Если сообщения конкретного вызова нельзя отделить, показать их недоступность. Добавить флажок расширенного ответа, время выполнения в 1С, цепочку причин и короткий стек. Проверить сокращение прямой ошибки, сохранение деталей вложенного сбоя и неизменность исходного текста при обоих положениях флажка.
- 4.2 Показывать базу, версию, режим и свежесть готовности; проверить потерю связи и ответа restart без автоматического запуска второго клиента, обновить диагностику.

## Результат и доказательства

19.11.2026: на отдельной копии файловой базы 1С 8.5.1.1529 через HTTP proxy пройдены 28 из 28 проверок. В открытой форме проверен флажок «Расширенная диагностика (Fork)». Подпись слева, флажок справа, установлен по умолчанию. Сохранение проверено под ролью с правом «Сохранение данных пользователя». После перезапуска значение восстановилось. После снятия флажка новые поля исчезли и при повторном чтении ранее принятой операции. Исходный текст ошибки совпал при обоих положениях флажка.

| Сценарий сравнения | Что есть в новом ответе |
|---|---|
| Прикладная ошибка с номером документа 000012 и кодом справочника K-017 | В result.error тот же текст. Дополнительно код и источник сбоя, строка, база, версия и режим на момент принятия операции. |
| Поле доступно только для чтения или отсутствует | Старый текст сохранён. В diagnostics.error_location добавлены read_only_field либо missing_field, имя поля и строка. |
| Явная категория нарушения прав или отказ Toolkit | Сохранён исходный результат. Выделяются permission_denied и mode_deny. |
| Успех после ошибки с сообщениями | error=null. Для сообщений выставлен статус unavailable с причиной call_buffer_not_isolated. |

Продолжение 4.1 от 19.11.2026. На двух изолированных копиях 1С 8.5.1.1529 через HTTP proxy проверена запись текстового документа на клиенте и сервере. С правом «Вывод» файл записался. Без права 1С вернула «Вывод запрещен», файл не создан. Цепочка `ИнформацияОбОшибке()` содержит категории выполнения и использования BSL. Код и дополнительная информация пусты, категории нарушения прав, запрета функциональности и доступа к локальному файлу отсутствуют.

- Для этого отказа добавляются `diagnostics.code=platform_runtime_error`, `source=1c_runtime`, категория BSL и `diagnostics.permissions.output=false`. Значение права получает сама обработка через `ПравоДоступа("Вывод", Метаданные)` для текущего пользователя.
- Прикладное исключение с побайтно совпадающим полным текстом даёт `application_error` и `1c_application`. Явная категория нарушения прав по-прежнему даёт `permission_denied`, а отказ Toolkit — `mode_deny`.
- Ошибка отсутствующего поля на том же стенде остаётся `missing_field` независимо от права «Вывод». `result.error` совпадает со старым ответом и сохраняется при снятии флажка.

Пункт 4.1 закрыт по согласованному поведению и 74 проверкам на двух копиях базы. Если платформа не сообщает точную причину, Toolkit сохраняет исходный текст и возвращает доступную категорию. Право «Вывод» фиксируется отдельно как свойство среды. Прогон без права (локальный путь `.local/task006-output-20261119/retry/denied/results.json`) · Прогон с правом (локальный путь `.local/task006-output-20261119/retry/allowed/results.json`).

Дополнение 19.11.2026. На отдельной файловой базе 8.5.1.1529 через MCP и HTTP proxy прошли 14 проверок `diagnostics.execution_ms`. Успешная команда показала 0 мс, исключение после заданной задержки — 200 мс на клиенте и сервере. После истечения 30 мс ожидания замер появился только с поздним результатом той же операции и составил 1500 мс. Короткая команда следом показала 0 мс при 2378 мс от регистрации до результата в proxy. При отказе до исполнения поле отсутствовало. Снятие флажка скрыло диагностику и у ранее завершённой операции. Протокол прогона (локальный путь `.local/task006-execution-ms-20261119/final/results.json`).

Расширение 19.11.2026. Флажок переименован в «Расширенный ответ (Fork)», ключ настройки сохранён. Замер добавлен в обычные `execute_code`, `execute_query`, `get_object_by_link` и `find_references_to_object`. Проверены чтение подписи из открытой формы, ответы с замером и со снятым флажком, сохранение исходного текста ошибки и отсутствие замера у `get_link_of_object`. На файловой базе 8.5.1.1529 прошли 27 проверок HTTP proxy и по 24 проверки файлового моста и встроенного MCP. Клиент-серверные фоновые задания в этот прогон не входили. HTTP proxy (локальный путь `.local/task006-expanded-response-20261119/http-final/results.json`) · Файловый мост (локальный путь `.local/task006-expanded-response-20261119/file/results.json`) · Встроенный MCP (локальный путь `.local/task006-expanded-response-20261119/embedded/results.json`).

Дополнение 19.11.2026. В расширенные ответы `execute_code` и `execute_code_operation` добавлены цепочка причин и короткий прикладной стек. На файловой базе 8.5.1.1529 через HTTP proxy прошли 27 проверок. При прямой ошибке сохранились одно звено и один кадр. При сбое подписки на проведение сохранились три звена и четыре кадра, включая вызов проверки внутри подписки. В обоих случаях скрыты два распознанных серверных кадра или четыре клиентских. Текст ошибки совпал с исходным прогоном. Проверены повторное чтение через `get_operation`, отключение флажка и остановка фильтра на незнакомом кадре. Протокол (локальный путь `.local/task006-error-stack-impl-20261119/final/results.json`).

Уточнение 19.11.2026. Для прямой ошибки на известной строке опускаются дублирующие цепочка, стек и счётчик кадров. В повторном прогоне на 1С 8.5.1.1529 через HTTP proxy прошли 26 проверок. Обычный ответ при обращении к отсутствующему полю сократился с 614 до 225 байт компактного JSON на клиенте и сервере. В ответе журнала сохранилось структурированное место ошибки. При проведении три звена и четыре кадра совпали с предыдущим прогоном. Исключение с кодом и вложенный вызов с одной причиной и двумя кадрами сохранили оба поля. Исходный текст ошибок совпал с предыдущим прогоном. Протокол (локальный путь `.local/task006-compact-error-20261119/final/results.json`).

4.2 подтверждён на HTTP-маршруте через proxy. Наблюдались база, версия, режим разрешений и время подтверждённого контакта. Оснастка отбросила ответ на реальный перезапуск. После остановки тестового процесса статус стал disconnected. Порог свежести и ожидание перезапуска сокращены только на стенде.
