# Таблицы и меню: прогон 18 ноября 2026

Стенд: файловая каркасная база, тонкий клиент 8.5.1.1529, внешний Toolkit через зарегистрированный MCP. Сборка: [table-v3.epf](../build/http-mvp/table-v3.epf), SHA-256 `97FEF2DB0C0CAA41950C824B6754B60D550F03F3B915BED5A491339337B08A5F`. Базовый ZIP от 17 ноября относится к предыдущей сборке.

На штатной табличной части «Список номенклатуры» проверены read/find/select/add/fill/delete, чтение второй страницы и отказ stale_target при использовании ID прежнего снимка после изменения. В двух строках с одинаковым количеством неоднозначный delete вернул ambiguous_target. По количеству и цене вместе удалена одна строка из двух. Черновик закрыт без записи; запрос к базе: ноль приходных накладных.

Для числовой проверки в add/fill передавать, например, `{"column":"Цена","number":3}`. Ответ содержит отображение `3,00`, проверка сравнивает числа. Вариант `text` сравнивает текст точно, в том числе ведущие нули. В условиях where.equals ожидается отображаемый текст; например, для этой цены — `"3,00"`.

Без allow_navigation read/find видят только выделение. С разрешением менеджер выделяет строки средствами платформы; охват — строки интерфейса, а не все записи базы. Новый снимок заменяет предыдущий; next_cursor читает продолжение сохранённого снимка. Навигация может менять выделение. Проверены строки табличной части; иерархические и большие динамические списки этим прогоном не покрыты.

У группы «Отчеты» Expand и Collapse оба завершились нативным исключением на стадии invoke. В дереве до и после одна и та же команда «МВП отчет»; свойство видимости у группы недоступно. Наличие команды не подтверждает раскрытие. Результат — action_not_confirmed; автоматического повторного нажатия нет.
