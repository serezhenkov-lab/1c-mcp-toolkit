# Управление тест-клиентом через встроенный HTTP/MCP

Toolkit остаётся внешней обработкой EPF. Менеджер и тест-клиент работают в одной
файловой базе на Windows, тонкий клиент 8.5.1.1529. Python proxy и сценарный runner
для эксплуатации не требуются. Ограниченный MVP 26.11.17.1802 проверен;
[протокол](../openspec/changes/upravlenie-test-klientom/http-mvp-verification.md)
отделяет его от полной открытой матрицы v1/TE. Комплект: `build/http-mvp`.

Текущий состав стенда и примеры на штатных объектах описаны в
[каркасной базе](carcass-test-base.md). Агент обращается к ней через зарегистрированный
MCP `toolkit-carcass-85`, с видимыми вызовами инструментов.

## Запуск

1. Открыть EPF в сеансе с ключом `/TESTMANAGER`, выбрать «Встроенный сервер» и порт.
   Прямые адреса: `http://127.0.0.1:<порт>/api/<инструмент>` и
   `http://127.0.0.1:<порт>/mcp`. Для чтения JSON выбрать соответствующий формат.
2. В блоке «Тест-клиент текущей базы» указать пользователя и при необходимости
   пароль. Пользователь и порт сохраняются при изменении. Порт по умолчанию 1538,
   его можно изменить в «Дополнительных настройках». Пароль действует только
   в текущем сеансе. При пустом поле клиент запускается без аргумента пароля.
3. Для текущего MVP отключить анонимизацию штатным флажком: при включённой
   анонимизации `test_*` возвращают `operation_result_policy_not_ready`.
   Выбрать режим подтверждений осознанно: `ask` показывает обычную форму
   разрешения, `deny` запрещает действия, `session_allow` действует до конца сеанса.
   Режим можно установить через MCP [командой set_approval_mode](approval-control.md),
   например `{"mode":"session_allow"}`; менять поле вручную при каждом запуске не требуется.
4. Вызвать `test_session/start` с `params.profile_id: "local"` (для ранее сохранённой
   настройки продолжает действовать её ID). Для уже запущенного клиента
   используется явный `attach`; он не даёт право остановки чужого процесса.
5. В завершение закрыть формы и вызвать `test_session/stop`. Штатная остановка
   проверяет PID, время запуска, базу и токен собственного запуска. Закрытие
   основного окна через общий `test_action/close` запрещено.

Профиль восстановится при следующем открытии EPF. После перезапуска менеджера
нужен новый `attach`; прежние UI-ID и разрешения не восстанавливаются.

## Операции и наблюдение

Все семь `test_*` отображаются в штатном журнале справа на основной форме Toolkit:
запрос с параметрами, первоначальный ответ, состояния ожидания/выполнения и
асинхронный окончательный результат либо ошибка. ID запроса/операции позволяют
связать записи. Повторное чтение результата отображается как ответ на запрос,
повтор callback не дублирует запись завершения. Длинная запись сокращается до
16000 символов с отметкой; полный ответ MCP сохраняется, общий предел лога 70000
не меняется. Журнал формы не заменяет устойчивый журнал операций.

Все `test_*` требуют `request_id`, UI-команды также требуют живой `session_id`.
Запрос отправляется один раз. Ответ `queued/running/awaiting_approval` наблюдается
через `test_session/status` с `params.operation_id`. Сам `status` чтения операции
не создаёт новую запись журнала. Первое обращение может вернуть
`operation_store_unavailable`, пока журнал инициализируется; при `operation_id=null`
команда ещё не принята.

При потере ответа сохранять тот же `request_id` и точные параметры. Изменение
параметров с занятым ключом даёт `request_conflict`. `unknown` и
`execution=unknown` требуют остановить мутации и сверить существующую операцию,
UI и базу. Новым ключом неизвестное действие не повторять.

## Разделы, меню и командные панели

`test_inspect` предоставляет три отдельные области:

| action | Что читается |
|---|---|
| `tree` | Дерево формы, доступные свойства и редактор |
| `command_interface` | Нативные разделы, группы меню и команды окна |
| `command_bars` | Командные панели формы и её таблиц |

У чтения `command_interface` и `command_bars` задаётся окно; `element` не передаётся.
Общие ограничения: `params.depth` 0–32, `params.max_nodes` 1–5000.
`complete/truncated/reason` и `coverage` относятся к запрошенной области.
Непрошенная область не считается пустой. `table_additions` остаётся неподдержанной.

Типы командного интерфейса: `command_interface`, `command_group`, `command_button`.
У них нет `name`, `visible`, `enabled`, `read_only`, `editing`: возвращаются `null`
и `property_not_supported_for_type`. Они не подменяются свойствами кнопки формы.
Точная адресация — `element.id` из свежего inspect либо селектор
`type/title/path/scope`. В пути меню используются заголовки родительских групп;
в обычном дереве и панелях — имена элементов. Дубликаты дают `ambiguous_target`.

Пример нажатия раздела:

```json
{
  "request_id": "nav-001", "session_id": "<session>", "action": "click",
  "window": {"id": "<main-window>"},
  "element": {"selector": {
    "scope": "command_interface", "type": "command_button",
    "title": "Проверка интерфейса", "path": ["Панель разделов"]
  }},
  "params": {}
}
```

После выбора раздела повторить `inspect/command_interface`, затем нажать точную
команду. `test_action/expand` и `collapse` адресуют нативную `command_group`;
на группе «Отчёты» Expand не подтвердился, прямая команда внутри группы работает.
После неизвестного исхода разворачивания нельзя автоматически повторять действие.
Команды панелей — обычные `button` со `scope=command_bars`. Поиск выполняется
заново перед действием; неполный поиск не разрешает нажатие. Штатный API проверяет
доступные текущей роли команды. Отсутствие команды не означает отсутствие
поддержки всего класса объектов.

После изменения заголовка формы нативный API может выдать другой объект окна.
При `stale_target` сначала прочитать окна и дерево заново; прежний ID не
перенаправляется автоматически. Для длинной цепочки допустим однозначный селектор
по `form_name`; наличие второго такого окна остановит действие.

## Ввод и результаты

| test_input/action | params | Проверка |
|---|---|---|
| `text` | `{"text":"строка"}` | Точное представление, включая пустую строку |
| `number` | `{"value":12.5}` | Каноническое представление числа платформой |
| `date` | `{"value":"2026-11-17"}` | ISO-дата или `2026-11-17T09:30:00`, без зоны |
| `check` | `{"checked":true}` | Двухсостоянийный флажок |
| `select` | `{"choice":{"list_value":"Второй"}}` | Полный однозначный список выбора |

Тип выбирается явно. Число ограничено диапазоном ±999999999999999; дробная часть
должна помещаться в поле. Невозможная календарная дата отклоняется до ввода.
`expected/actual` содержат представление, `typed_expected` — типизированное
ожидание вызывающего. Подтверждение ввода не заменяет проверку типа и сохранения
запросом. Текстовый ввод по-прежнему сравнивает строки точно: `12,50` и `12,5`
различаются. Отказ сверки не запускает альтернативный ввод.

Кнопки, вкладки и закрытие формы доступны через `test_action`. Диалог сохранения
или вопрос платформы требует отдельного явно адресованного ответа. Результаты
читаются через `inspect/values`, `tree`, `messages`; сохранение — через
`execute_query` в той же обработке. Для снимка клиента:
`get_screenshot` с `target=test_client` и `session_id`.

Поддержка зависит от доступного штатному API действия. Не входят в MVP:
изменение неразличимых строк таблицы, выбор ссылочного значения через такую
строку, `click_group` карточки, открытие значения ячейки и полный разбор
произвольного MXL. Читаемый текст результата обычного отчёта поддерживается.
